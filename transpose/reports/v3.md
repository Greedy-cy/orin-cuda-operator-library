# Transpose v3：blockRows 配置扫描

## 1. 实验问题

v2 用 `32×8=256` 线程处理一个 `32×32` tile，每线程循环搬运 4 个元素。v3
将同一个 padded kernel 模板化，只扫描 `blockRows=4/8/16/32`：

| blockRows | Threads/block | Items/thread |
|---:|---:|---:|
| 4 | 128 | 8 |
| 8 | 256 | 4 |
| 16 | 512 | 2 |
| 32 | 1,024 | 1 |

tile、padding、全局内存顺序、一次 block barrier 和边界判断都保持不变。目标是
用实测选择配置，而不是把 occupancy 或线程数当作孤立优化目标。

## 2. 扫描结果

### `4096×4096`

| blockRows | Median | 有效带宽 | 峰值占比 | 相对最佳 | 正确性 |
|---:|---:|---:|---:|---:|---|
| 4 | 1.423344 ms | 94.297470 GB/s | 92.09% | 0.999× | PASS |
| **8** | **1.421248 ms** | **94.436532 GB/s** | **92.22%** | **1.000×** | PASS |
| 16 | 1.524464 ms | 88.042569 GB/s | 85.98% | 0.932× | PASS |
| 32 | 3.307488 ms | 40.579960 GB/s | 39.63% | 0.430× | PASS |

### 非对齐 `1000×1023`

| blockRows | Median | 有效带宽 | 相对最佳 | 正确性 |
|---:|---:|---:|---:|---|
| 4 | 0.097952 ms | 83.551126 GB/s | 0.965× | PASS |
| **8** | **0.094512 ms** | **86.592178 GB/s** | **1.000×** | PASS |
| 16 | 0.104496 ms | 78.318786 GB/s | 0.904× | PASS |
| 32 | 0.214864 ms | 38.089210 GB/s | 0.440× | PASS |

`blockRows=8` 在规则与非对齐矩阵都最佳。4 与 8 在主尺寸只差 0.15%，不足
3%，因此保留 v2 已使用且每线程循环更短的 8；16 和 32 作为负优化保留。
v3 的 1.421248 ms 与 v2 的 1.417264 ms 差异 0.28%，也不构成新收益。

## 3. Nsight Compute：为什么更多线程不一定更快

| 指标 | BR=4 | BR=8 | BR=16 | BR=32 |
|---|---:|---:|---:|---:|
| NCU duration | 1.45 ms | 1.46 ms | 1.58 ms | 3.41 ms |
| Memory throughput | 79.47% | 79.39% | 73.33% | 34.00% |
| Compute throughput | 35.88% | 36.41% | 39.36% | 15.98% |
| Issue slots busy | 36.55% | 36.85% | 39.62% | 17.53% |
| No eligible warp | 63.48% | 63.15% | 60.37% | 82.18% |
| Active warps / scheduler | 11.75 | 11.46 | 10.96 | 7.67 |
| Eligible warps / scheduler | 0.57 | 0.68 | 1.02 | 0.43 |
| Registers / thread | 29 | 22 | 20 | 16 |
| Block limit: warps | 12 | 6 | 3 | **1** |
| Block limit: shared memory | 12 | 12 | 3 | **1** |
| Theoretical occupancy | 100% | 100% | 100% | **66.67%** |
| Achieved occupancy | 98.39% | 96.83% | 92.24% | **63.95%** |

BR=4 虽有略高 occupancy，但每线程 8 次循环带来更多地址/循环状态，性能没有
超过 BR=8。BR=16 每块 512 线程，使可驻留 block 数减少，实际带宽下降。BR=32
每块 1,024 线程且每块仍独占一个 4,224-byte tile；warps/shared-memory 两项都
把驻留限制到 1 block，occupancy 只有 63.95%，`No eligible warp` 升至 82.18%，
因此出现 2.33× 负优化。

## 4. Nsight Systems 与 Sanitizer

选择 BR=8 后，`4096×4096` 的 6 个 kernel 实例 nsys median 为
**1.415792 ms**。`1000×1023` 的 memcheck 为 0 errors 且 bitwise PASS。
v3 的 kernel 内存与同步逻辑和已通过 memcheck/synccheck/racecheck 的 v2 相同，
本版本新增的四个模板配置也都在规则与非对齐输入上通过结果验证。

## 5. 决策与下一步

v3 没有超过 v2，价值在于排除了“增加线程数会更快”的猜测，并为 Orin 选择了
`32×8` block。v4 将探索对齐矩阵的向量化访问；必须保留 v2/v3 的标量边界路径，
并检查 `float4` 是否真的减少指令或提高带宽。由于 v2 已达 92.48% 峰值，v4
很可能不足 3% 或成为负优化，结果以实测为准。
