# Transpose v2：`32×33` padding 消除 bank conflict

## 1. 单变量实验

v2 相对 v1 只修改一处：

```cpp
// v1
__shared__ float tile[32][32];

// v2
__shared__ float tile[32][33];
```

block/grid、每线程 4 元素循环、全局访问和边界判断均不变。额外一列让相邻
shared 行的起始 bank 轮转，转置读取时线程 `tx=0..31` 不再映射到同一个 bank。

## 3. Sanitizer

对 `1000×1023` 执行 memcheck，对 `37×65` 分别执行 synccheck/racecheck。
结果为 0 errors、0 hazards，所有输出 bitwise PASS。padding 没有改变边界
语义，也未引入 shared 越界。

## 4. Nsight Systems

`4096×4096` 的 6 个 kernel 实例 median 为 **1.413168 ms**，与 CUDA Event
的 1.417264 ms 接近；v1 为 2.402464 ms，对应 nsys 加速 1.70×。

| L1/TEX throughput | 97.45% | 23.15% | bank-conflict replay 大幅下降 |
| L2 throughput | 47.54% | 79.76% | 有效全局流量占比提高 |

| Issue slots busy | 21.61% | 36.96% | 提高 |
| No eligible warp | 78.39% | 63.06% | 降低 |
| Active warps / scheduler | 11.31 | 11.47 | 基本不变 |

指令数完全相同，进一步证明收益来自访问布局而非代码量变化。

### Bank conflict 量化

| 指标 | v1 | v2 | 变化 |
|---|---:|---:|---:|
| Shared load requests | 524,288 | 524,288 | 不变 |
| 平均 bank conflict | 32.5-way | **1.1-way** | 接近理想 |
| Bank conflicts | 16,334,423 | **64,297** | 下降 99.61% |
| Shared-load wavefronts | 17,040,797 | **599,491** | 下降 96.48% |

ncu 对 v2 仍报告少量 1.1-way 冲突，但相较 v1 已消除主要结构性冲突。性能已达
峰值带宽的 92.48%，剩余提升空间有限。

## 6. 下一步

v3 不再修改 tile 尺寸或 padding，而是比较每线程处理元素数：保留 `32×32`
tile 与 33 列 padding，扫描 `blockRows=4/8/16`，用同一源码的运行时参数选择
三个专用 kernel。目标是判断当前 8 行配置是否最适合 Orin，而不是假设更多或
更少线程一定更快。若差异不足 3%，保留结构最简单的 8 行配置。
