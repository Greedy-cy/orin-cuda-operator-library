# Transpose v4：float4 向量化实验与最终收口

## 1. 优化设计

对 `rows`、`cols` 均为 32 倍数的矩阵，v4 使用 `8×32=256` 线程：

- 每线程用一次 `float4` 读取输入行中的 4 个连续元素；
- 将四个分量写入 `tile[32][33]`；
- 转置读取 shared tile，组成一个 `float4`；
- 每线程一次 `float4` 写回输出的 4 个连续元素。

非对齐矩阵完整回退到 v2 的 `32×8` 标量 padded kernel。对齐条件使用 32 而
不仅是 4，保证每个 tile 无边界分支、每行起始地址和 `float4` 都对齐。

## 2. 正确性与性能

| Rows | Cols | v4 路径 | v2 Median | v4 Median | 相对 v2 | 正确性 |
|---:|---:|---|---:|---:|---:|---|
| 3 | 5 | scalar fallback | 0.007360 ms | 0.007376 ms | 1.00× | PASS |
| 1,024 | 1,024 | float4 | 0.096192 ms | 0.095808 ms | 1.00× | PASS |
| 4,096 | 4,096 | float4 | **1.417264 ms** | 1.421760 ms | **1.00×** | PASS |
| 1,024 | 4,096 | float4 | 0.361280 ms | 0.362480 ms | 1.00× | PASS |
| 4,096 | 11,008 | float4 | 3.859216 ms | 3.863584 ms | 1.00× | PASS |
| 1,000 | 1,023 | scalar fallback | 0.094976 ms | 0.095152 ms | 1.00× | PASS |

所有差异都小于 1%，没有一个形状达到 3% 收益。v4 是正确但无性能收益的负优化。

## 3. Sanitizer

- 对齐 float4 路径：`96×160`；
- 非对齐标量路径：`1000×1023`。

两条路径 memcheck 均为 0 errors；float4 路径 synccheck 为 0 errors、racecheck
为 0 hazards；输出全部 bitwise PASS。

## 4. Nsight Systems

`4096×4096` 的 6 个 v4 kernel 实例 median 为 **1.425808 ms**，v2 为
1.413168 ms。nsys 同样显示 v4 没有提升，排除了 CUDA Event 测量偶然性。

## 5. Nsight Compute：指令更少但没有更快

| 指标 | v2 scalar padded | v4 float4 | 变化 |
|---|---:|---:|---|
| Kernel duration | 1.45 ms | 1.45 ms | 持平 |
| Memory throughput | 79.76% | 79.07% | 持平 |
| L1/TEX throughput | 23.15% | 22.93% | 持平 |
| L2 throughput | 79.76% | 79.07% | 持平 |
| Compute throughput | 36.51% | 13.55% | 指令工作下降 |
| Issue slots busy | 36.96% | 12.33% | 下降 |
| No eligible warp | 63.06% | **87.68%** | 内存等待占比更突出 |
| Active warps / scheduler | 11.47 | 11.40 | 不变 |
| Eligible warps / scheduler | 0.68 | 0.16 | 下降 |
| Registers / thread | 22 | 19 | 下降 |
| Achieved occupancy | 95.96% | 95.69% | 不变 |
| Executed instructions | 16,908,288 | **5,636,096** | 下降 66.7% |

float4 确实把执行指令减少了三分之二，但全局最小流量仍是一次读和一次写，v2
已经达到约 92.5% 的锁频峰值。减少指令只让 issue slot 更空闲，无法缩短内存
完成时间，因此端到端性能持平。这个结果说明向量化是手段，不是独立性能目标。

## 6. 最终稳定性

最终选择 v2。每次 warmup 20、测量 50 次取 median，再独立运行 5 轮：

| 形状 | 五轮 median（ms） | 最大跨度 |
|---|---|---:|
| `4096×4096` | 1.420560 / 1.419328 / 1.418320 / 1.419536 / 1.417200 | 0.24% |
| `1000×1023` | 0.094464 / 0.095168 / 0.094928 / 0.095264 / 0.094256 | 1.07% |

均低于 3% 波动阈值。

## 7. 停止条件与最终结论

- v0 和最终 v2 对规则、矩形、非对齐尺寸均 bitwise 正确；
- v2/v4 的复杂 shared/向量路径通过 memcheck、synccheck、racecheck；
- v2 主尺寸 1.417264 ms、94.70 GB/s、峰值占比 92.48%；
- 相对 v0 8.878576 ms 加速 **6.26×**；
- 最终瓶颈是最小的一读一写内存流量；
- v3 形状扫描与 v4 向量化连续两个方向都未超过 3%。

因此 Transpose standalone 阶段选择 v2 收口；v3/v4 保留为配置扫描与负优化
该版本作为优化反例保留，不作为 dispatcher 的默认实现。
