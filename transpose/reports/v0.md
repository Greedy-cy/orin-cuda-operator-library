# Transpose v0：直接全局内存转置 baseline

## 1. 实现与预期瓶颈

每个线程负责一个输入元素，block 为 `32×8`：

```text
output[col * rows + row] = input[row * cols + col]
```

同一 warp 的 `col` 连续，因此输入读取合并；输出地址间隔为 `rows`，因此写入
不合并。v0 有意保留这个问题，作为 shared-memory tiled transpose 的基准。

## 2. 环境与测量

| 项目 | 值 |
|---|---|
| GPU | Jetson Orin Nano Super，8 SM，sm_87 |
| CUDA | 12.6 |
| 锁频 | MAXN_SUPER，GPU 1020 MHz，EMC 3199 MHz |
| 编译 | `-O3 -lineinfo -std=c++17 -arch=sm_87` |
| 计时 | warmup 10，CUDA Event 30 次取 median |
| 峰值口径 | 128-bit LPDDR5，3199 MHz DDR，约 102.4 GB/s |

有效带宽按输入读取与输出写入的最小流量 `2 * rows * cols * sizeof(float)`
计算。它用于衡量有用数据移动，不包含非合并事务造成的放大流量。

## 3. 正确性与性能

Transpose 只是搬运数据，因此要求与 CPU reference bitwise 一致，最大绝对误差
必须为 0。

|---:|---:|---:|---:|---:|---|
| 3 | 5 | 0.007488 ms | 0.016026 GB/s | 0.02% | PASS |
| 1,024 | 1,024 | 0.564832 ms | 14.851511 GB/s | 14.50% | PASS |
| 4,096 | 4,096 | **8.878576 ms** | **15.117033 GB/s** | **14.76%** | PASS |
| 1,024 | 4,096 | 2.226976 ms | 15.067263 GB/s | 14.71% | PASS |

规则大矩阵稳定在约 15 GB/s；非对齐边界略低，但仍正确。

## 4. Sanitizer

```bash
compute-sanitizer --tool memcheck --error-exitcode=1 \
  ./build/transpose_v0 --rows=1000 --cols=1023 --warmup=1 --repeat=2
```

结果为 `ERROR SUMMARY: 0 errors`、`correct=PASS`，覆盖 x/y 两个方向的边界
判断。

### 事务放大证据

`4096×4096` 有 524,288 个 warp 级 load 请求和相同数量的 store 请求：

| 访问 | L1TEX requests | L1TEX sectors | Sectors/request |
|---|---:|---:|---:|
| Global load | 524,288 | 2,097,152 | 4 |
| Global store | 524,288 | 16,777,216 | **32** |

读取的 4 sectors/request 正好覆盖一个 warp 的 128 bytes；写入的 32
sectors/request 表示每个线程占用独立 sector。ncu 直接提示 global store 每个
32-byte sector 平均只使用 4 bytes，并统计 18,874,368 个总 sector 中有
14,680,064 个多余，占 **77.8%**。这就是 v0 性能低的直接证据。

## 7. 下一步

v1 使用 `32×32` shared-memory tile：先合并读取输入到 tile，再交换 block 坐标
并合并写出。block 仍使用 `32×8` 线程，每线程处理 tile 中 4 个元素。v1 暂时
使用 `tile[32][32]`，保留转置读取时的 shared-memory bank conflict，留给 v2
用 `tile[32][33]` 单独消除。
