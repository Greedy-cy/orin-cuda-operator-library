# RMSNorm v4：线程配置扫描与最终收口

## 1. 扫描设计

v4 将 v3 的 float4 与标量 kernel 模板化，允许 `128/256/512` threads。命令行
`--threads=0` 使用自动选择；显式参数用于复现实验。规约、float4 数据路径、
epsilon 和结果验证都不变。

对 hidden=1024，float4 数量为 256，三个配置每线程分别处理 2/1/约半数线程
无元素；对 hidden=4096，float4 数量为 1024，每线程处理 8/4/2 个。

## 2. hidden=1024 扫描

| Tokens | 128 threads | 256 threads | 512 threads | 选择 |
|---:|---:|---:|---:|---|
| 1 | 0.008704 ms | 0.008448 ms | 0.008432 ms | 差异不足 1% |
| 32 | 0.010224 ms | **0.009968 ms** | 0.011264 ms | 256 |
| 512 | 0.053312 ms | **0.053072 ms** | 0.066656 ms | 256 |
| 2,048 | 0.182368 ms | **0.182016 ms** | 0.231008 ms | 256 |

128 没有优于 256；512 因一半线程不处理向量，在中大 token 数慢 22-27%。因此
hidden=1024 选择 256。

## 3. hidden=4096 扫描

| Tokens | 128 threads | 256 threads | 512 threads | 观察 |
|---:|---:|---:|---:|---|
| 1 | 0.010656 ms | 0.009568 ms | **0.009200 ms** | 512 快 4.0% |
| 32 | 0.015696 ms | **0.014464 ms** | 0.016448 ms | 512 慢 13.7% |
| 512 | 0.222496 ms | 0.187552 ms | **0.184864 ms** | 512 快 1.5% |
| 2,048 | 0.852304 ms | 0.712160 ms | **0.703488 ms** | 512 快 1.2% |

512 只在单 token 超过 3%，而该形状绝对差仅 0.37 µs；在 512/2048 tokens 的
收益低于 3%，并在 32 tokens 明显回退。为避免对少量点过拟合，hidden=4096
也保留 256。

最终自动规则因而是 1024→256、4096→256；源码简化为统一返回 256，并在注释中
保留扫描结论。显式线程参数仍可复现负优化。

ncu 多 pass 测量中 256 反而略快于 512，进一步说明两者差异不稳健。128 虽执行
指令最少，但每线程串行处理 8 个向量、eligible warp 仅 0.10，明显更慢。

## 6. Sanitizer 与稳定性

- `17×1003` 自动标量路径 memcheck：0 errors；
- `17×1024` 自动 float4 路径 synccheck：0 errors，racecheck：0 hazards；
- 所有配置和完整形状矩阵均通过误差阈值。

五轮稳定性：

| 形状 | 每轮设置 | 五轮 median（ms） | 最大跨度 |
|---|---|---|---:|
| `2048×4096` | warmup 20 / repeat 50 | 0.713536 / 0.708240 / 0.715328 / 0.710560 / 0.712288 | 1.00% |
| `17×1003` | warmup 50 / repeat 200 | 0.011264 / 0.011136 / 0.011264 / 0.011104 / 0.011280 | 1.58% |

nsys 中 `2048×4096` 的 6 个自动 kernel 实例 median 为 **0.705280 ms**。

## 7. 停止条件与最终结论

- v0 与 v3/v4 对常规、单 token、非对齐 hidden 均正确；
- float4 与标量路径通过 memcheck/synccheck/racecheck；
- 主尺寸和非对齐小尺寸稳定性均低于 2%；
- v3 主尺寸相对 v0 为 **4.20×**；
- v4 的配置变化没有稳定超过 3%，部分形状出现明显负优化；
- 最终瓶颈为两次输入读取和 weight/output 的全局流量，Memory throughput 约
  82%，继续调整 block 线程数没有证据支持。

FP32 standalone 最终选择 v3 的 256-thread float4 + scalar fallback。v4 保留为
配置扫描材料。FP16 输入、FP32 accumulation 留到 dtype 扩展阶段，不改变本轮
FP32 benchmark 口径。
