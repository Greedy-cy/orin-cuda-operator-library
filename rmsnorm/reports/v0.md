# RMSNorm v0：四 kernel 与中间缓冲 baseline

## 1. 实现

v0 有意将一次 RMSNorm 拆为四步：

1. `square_kernel`：读输入，写逐元素平方缓冲；
2. `row_inverse_rms_kernel`：每行一个 block，用 shared tree reduction 读取平方
   缓冲并写一个 inverse RMS；
3. `normalize_kernel`：再次读输入和 inverse RMS，写 normalized 缓冲；
4. `weight_kernel`：读 normalized 与 weight，写最终输出。

这种实现简单、边界明确，但包含 4 次 kernel launch、两块完整中间缓冲以及多次
全局往返，作为后续融合的基准。

## 2. 环境与口径

| 项目 | 值 |
|---|---|
| GPU | Jetson Orin Nano Super，8 SM，sm_87 |
| CUDA | 12.6 |
| 锁频 | MAXN_SUPER，GPU 1020 MHz，EMC 3199 MHz |
| 编译 | `-O3 -lineinfo -std=c++17 -arch=sm_87` |
| 计时 | warmup 10，完整四 kernel 运行 30 次取 median |
| epsilon | `1e-5` |

报告的“理想口径带宽”按融合算法的输入、weight、输出三份 FP32 数据计算：
`(2*tokens*hidden + hidden)*4 / time`。v0 实际的逻辑元素流量约为 9C：
square 2C、reduce C、normalize 3C、weight 3C，未把小的 inverse-RMS 数组计入。

## 3. 正确性与性能

CPU reference 使用 double 累加平方和。阈值为 `max_abs<=2e-4` 且
`max_rel<=2e-4`；本轮打印到 6 位小数均为 0。

| Tokens | Hidden | Median | 理想口径带宽 | 正确性 |
|---:|---:|---:|---:|---|
| 1 | 1,024 | 0.022352 ms | 0.549749 GB/s | PASS |
| 1 | 4,096 | 0.025520 ms | 1.926019 GB/s | PASS |
| 32 | 1,024 | 0.028848 ms | 9.229063 GB/s | PASS |
| 32 | 4,096 | 0.053168 ms | 20.030094 GB/s | PASS |
| 512 | 1,024 | 0.250800 ms | 16.740031 GB/s | PASS |
| 512 | 4,096 | 0.815648 ms | 20.589275 GB/s | PASS |
| 2,048 | 1,024 | 0.864144 ms | 19.419579 GB/s | PASS |
| 2,048 | 4,096 | **2.990064 ms** | **22.449434 GB/s** | PASS |

单 token 时数据量很小，四次 launch 固定成本占主导；大 token 数时多次中间内存
往返成为主要成本。

## 4. Sanitizer

在非对齐 `tokens=17, hidden=1003` 上执行 memcheck 和 synccheck，均为
`ERROR SUMMARY: 0 errors`，结果 PASS。shared tree reduction 的边界元素由每线程
循环自然处理，不要求 hidden 为 256 的倍数。

## 5. Nsight Systems：四个 kernel 的时间组成

`2048×4096`，每种 kernel 统计 6 个实例：

| Kernel | Median | 总时间占比 |
|---|---:|---:|
| square | 0.782336 ms | 26.2% |
| row inverse RMS | 0.584320 ms | 19.3% |
| normalize | 0.859376 ms | 28.4% |
| weight | 0.785536 ms | 26.1% |
| 四项中值之和 | **3.011568 ms** | 100% |

中值之和与 CUDA Event 的 2.990064 ms 接近。没有单个 kernel 独占全部时间；融合
需要同时删除 launch 和中间流量，而不是只优化 reduction。

## 6. Nsight Compute

| 指标 | Square | Reduce | Normalize | Weight |
|---|---:|---:|---:|---:|
| Duration | 866.27 us | 597.06 us | 966.75 us | 876.42 us |
| Memory throughput | 66.61% | 53.62% | 59.82% | 66.00% |
| Compute throughput | 16.31% | 23.32% | 42.41% | 46.39% |
| Issue slots busy | 16.36% | 23.48% | 42.62% | 46.66% |
| No eligible warp | 83.60% | 76.51% | 57.42% | 53.34% |
| Registers / thread | 16 | 16 | 16 | 18 |
| Achieved occupancy | 92.78% | 97.29% | 94.14% | 92.97% |
| Executed instructions | 4,096,000 | 4,347,904 | 11,730,944 | 11,730,944 |

四个 kernel 的 occupancy 都在 92% 以上，因此继续追求 occupancy 没有依据。
Square 和 reduce 的 `No eligible warp` 超过 75%，normalize/weight 也以全局数据
访问为主。最直接的优化是让一个 block 在寄存器/shared memory 中完成平方和、
归一化与权重乘法，删除中间缓冲及三次 launch。

## 7. 下一步

v1 每行一个 block，使用 shared tree reduction 计算平方和，并在同一个 kernel
中重新读取输入、乘 inverse RMS 与 weight 后直接写最终输出。它仍保留 v0 的
tree reduction，单独量化 fusion：launch 从 4 降到 1，逻辑元素流量从约 9C
降到约 4C（输入读取两次、weight 一次、输出一次），不在这一版同时引入 warp
shuffle。
