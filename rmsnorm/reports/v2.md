# RMSNorm v2：warp-shuffle 规约

## 1. 优化假设

v1 的平方和使用 256-thread shared tree reduction，共 9 次 full-block barrier，
dynamic shared memory 为 1,024 bytes。v2 保持单 kernel、256 线程、两次输入读取
和输出公式不变，只改规约：

1. 每个 warp 内用 shuffle 规约；
2. 8 个 warp leader 写 8 个 shared 值；
3. 第一个 warp 完成二级规约并广播结果。

full-block barrier 降为 2 次，dynamic shared memory 降至 32 bytes。

## 3. Sanitizer

`17×1003` 的 memcheck/synccheck/racecheck 分别为 0 errors、0 errors、0 hazards，
输出 PASS。所有 8 个 warp 始终参与两次 block barrier，非对齐 hidden 不改变
同步参与集合。

## 4. Nsight Systems

`2048×4096` 的 6 个 kernel 实例 median：

- v1 fused tree：0.912496 ms；
- v2 fused shuffle：**0.894656 ms**；
- nsys 加速：1.02×。

这与 CUDA Event 的 1.01× 同属小幅收益。

## 5. Nsight Compute

| 指标 | v1 tree | v2 shuffle | 变化 |
|---|---:|---:|---|
| Duration | 930.56 us | 916.86 us | 1.01× |
| Memory throughput | 66.84% | 67.75% | 略升 |
| L1/TEX throughput | 23.07% | 19.87% | shared 压力下降 |
| Compute throughput | 31.54% | 28.31% | 指令减少 |
| Issue slots busy | 32.01% | 28.48% | 指令减少 |
| No eligible warp | 68.17% | 71.52% | 内存等待相对占比上升 |
| Active warps / scheduler | 11.57 | 11.54 | 不变 |
| Eligible warps / scheduler | 0.48 | 0.40 | 略降 |
| Registers / thread | 16 | 16 | 不变 |
| Dynamic shared / block | 1,024 B | **32 B** | 下降 96.9% |
| Achieved occupancy | 97.10% | 96.28% | 基本不变 |
| Executed instructions | 9,273,344 | **8,167,424** | 下降 11.9% |

指令和 shared 用量明显下降，但 occupancy 没有提高，耗时只下降 1.5%。v2 把
规约成本压低后，硬件更明确地等待全局数据，支持下一版优化访问指令而不是继续
修改规约。

## 6. 下一步

v3 对 `hidden%4==0` 使用 `float4` 读取输入、weight 并写输出，非对齐 hidden
保留 v2 标量路径。它不减少算法字节数，目标是减少 load/store 与循环指令；
是否有效必须由 ncu 指令数和端到端时间共同决定。
