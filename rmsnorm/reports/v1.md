# RMSNorm v1：单 block 融合

## 1. 单变量优化

v1 每个 token 启动一个 256-thread block：

1. 每线程循环读取该行输入并累加平方和；
2. 使用与 v0 相同的 shared-memory tree reduction；
3. 所有线程读取最终 inverse RMS；
4. 再次读取输入，乘 inverse RMS 和 weight，直接写最终输出。

相比 v0，launch 从 4 降到 1，删除 squared/normalized 两块中间缓冲。逻辑元素
流量从约 9C 降到 4C：输入为规约和输出各读一次、weight 读一次、输出写一次。
规约算法保持不变，用来隔离 kernel fusion 的收益。

## 3. Sanitizer

在 `17×1003` 上执行 memcheck、synccheck、racecheck：分别为 0 errors、0
errors、0 hazards，输出 PASS。所有线程无条件参与 tree reduction barrier，非
对齐 hidden 只影响每线程循环次数，不产生分歧同步。

## 4. Nsight Systems

`2048×4096` 的 6 个融合 kernel 实例 median 为 **0.912496 ms**。v0 四类
kernel 的 median 之和为 3.011568 ms，对应 3.30×。时间线从每次 RMSNorm 四个
连续 kernel 缩减为一个，无中间 D2D copy。

融合使总执行指令下降约 70.9%，同时删除了中间全局流量。v1 occupancy 仍为
97.10%，而 eligible warp 仅 0.48，继续提高 occupancy 没有意义。当前规约使用
1 次初始 barrier 加 8 次 tree 阶段 barrier；hidden 较小时这些同步占比更高。

## 6. 下一步

v2 保持单 kernel、两次输入读取和 block 配置不变，只将 tree reduction 改为
warp shuffle + 每 warp 一个 shared 结果的二级规约。目标是把 full-block barrier
从 9 次降到 2 次，并把 dynamic shared memory 从 1,024 bytes 降到 32 bytes。
