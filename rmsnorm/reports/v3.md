# RMSNorm v3：float4 向量化与标量回退

## 1. 优化设计

v2 已把规约指令压低，但主形状 Memory throughput 为 67.75%，且端到端只比 v1
快 1.2%。v3 对 `hidden%4==0` 的行使用 `float4`：

- 平方和阶段每次读取 4 个输入并累加 4 个平方；
- 输出阶段每次读取一个 input `float4` 和 weight `float4`，写一个 output
  `float4`；
- reduction、256-thread block 和算法字节数不变；
- 非 4 对齐 hidden 完整回退到 v2 标量 kernel。

CUDA allocation 至少 256-byte 对齐，且 `hidden%4==0` 保证每行起点 16-byte
对齐。

## 3. Sanitizer

- `17×1003` 标量回退：memcheck 0 errors；
- `17×1024` float4：memcheck、synccheck 0 errors，racecheck 0 hazards；
- 两条路径输出均在误差阈值内。

这同时覆盖了向量地址对齐和非对齐 hidden 的边界逻辑。

## 4. Nsight Systems

`2048×4096` 的 6 个实例 median：

- v2 scalar shuffle：0.894656 ms；
- v3 float4：**0.707776 ms**；
- nsys 加速：1.26×。

## 5. Nsight Compute

| 指标 | v2 scalar | v3 float4 | 变化 |
|---|---:|---:|---|
| Duration | 916.86 us | 712.90 us | 1.29× |
| Memory throughput | 67.75% | **81.54%** | 更充分利用内存路径 |
| L1/TEX throughput | 19.87% | 23.59% | 提高 |
| Compute throughput | 28.31% | 14.64% | 指令占比下降 |
| Issue slots busy | 28.48% | 14.84% | 指令减少 |
| No eligible warp | 71.52% | 85.14% | 内存等待成为明确主导 |
| Active warps / scheduler | 11.54 | 11.10 | 略降 |
| Eligible warps / scheduler | 0.40 | 0.18 | 下降 |
| Registers / thread | 16 | 22 | 四分量临时值代价 |
| Achieved occupancy | 96.28% | 92.31% | 略降但性能显著提高 |
| Executed instructions | 8,167,424 | **3,383,296** | 下降 58.6% |

尽管寄存器增加、occupancy 下降，v3 仍快 26%，收益来自 load/store 与循环指令
下降、内存吞吐提高。这再次说明 occupancy 不是孤立优化目标。

## 6. 下一步

v4 根据 hidden 选择线程配置：为 1024 与 4096 分别扫描 128/256/512 threads，
保留 float4 和标量回退。目标是改善 hidden=1024 的线程工作量与小 token 并行度，
同时确认 4096 是否仍适合 256 threads。若扫描无超过 3% 的稳定收益，则选择 v3
并收口。
