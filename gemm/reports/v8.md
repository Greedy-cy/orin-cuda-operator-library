# GEMM v8：WMMA block tiling、shared 布局与 cp.async 流水

## 1. 目标与不变口径

v8 直接处理 v7 的 NCU 证据：每个 warp 独立从 global memory 加载 A/B，导致
L1/TEX 99.76%、long scoreboard 92.8%、Tensor compute throughput 17.32%。

数据类型和参考口径保持不变：FP16 A/B、FP32 Tensor Core accumulation、FP32 C；
cuBLAS 使用 `cublasGemmEx` 的 FP16 input / FP32 compute / FP32 output Tensor Op。
每个小版本只改变 kernel tile/流水/布局，不改变数据生成、正确性阈值或计时方式。

最终 v8 主路径包含：

- 256 threads / 8 warps；
- block output tile `128×128`，K tile 为 16；
- 每 warp 计算 `2×4` 个 `16×16` WMMA C fragments；
- A/B 两级 shared buffer；
- 每线程 16-byte `cp.async` global-to-shared copy；
- `commit_group`、`wait_group<1>` 与末组 `wait_group<0>`；
- shared A/B 每行增加 8 个 half 的 skew；
- M=16/32/48/64 等小 M 使用 16-row × 128-column 专用 kernel；
- 其他 16 对齐形状保留 v7 WMMA fallback，任意非对齐形状使用 scalar fallback。

## 3. v8.0：block-level shared tiling baseline

### 假设

一个 `64×128` block tile 包含 32 个 WMMA output tiles。8 个 warps 各计算 2×2
个 tiles，在 K 维共享 A `[64,16]` 与 B `[16,128]`。相对 v7，同一 A tile 被多个
N 方向 warps 复用，同一 B tile被多个 M 方向 warps 复用。

两级 shared buffer 用 cp.async 预取下一 tile；每个 K tile 完成 4 次 MMA/warp。

### 结果

1024³ 从 v7 的 2.293312 ms 降至 0.851648 ms，性能从 0.936 提至 2.522 TFLOP/s，
证明跨 warp shared 复用方向正确。但距离 FP16 cuBLAS 7.242 TFLOP/s 仍很远，
因此继续检查 barrier 粒度与 shared 布局。

## 4. v8.1：BK=32 的负优化

### 假设

将 BK 从 16 扩为 32，使一次双缓冲切换执行两轮 `16×16×16` WMMA，理论上可将
block barrier 次数减半。shared 从 12,288 B 增至 24,576 B，寄存器从 71 增至
74，仍无 spill。

### 结果与否决

1024³ 变为 0.900128 ms / 2.386 TFLOP/s，比 v8.0 慢 5.4%。M=16 专用路径为
0.481856 ms / 1.114 TFLOP/s，说明较粗 K tile 对 small-M 不坏，但不能弥补主路径
shared 容量、加载批次和调度变化的代价。

结论：barrier 次数不是当时的首要瓶颈，v8.1 作为负优化记录，主路径回到 BK=16。

## 5. v8.2：shared row skew

### 假设

WMMA 从 shared memory 加载矩阵 fragment 时，紧凑 stride 16/128 half 会让多行
映射到重复 bank 模式。给 A/B 每行增加 8 half（16 bytes）padding：

```text
A shared leading dimension: 16 -> 24 half
B shared leading dimension: 128 -> 136 half
```

global copy 仍以连续 16 bytes 为单位，只改变 shared destination 的行跨度。

### 结果

1024³ 从 v8.0 的 0.851648 ms 降至 **0.470624 ms**，性能从 2.522 提到
**4.563 TFLOP/s（1.81×）**。资源仅从 71 regs / 12,288 B 变为 70 regs /
14,848 B，无 spill，因此收益来自 shared 布局而不是 occupancy 增加。

同一布局下：

- M=16, N=K=4096：0.408128 ms / 1.315 TFLOP/s；
- 2048³：4.895168 ms / 3.510 TFLOP/s；
- 4096³：38.272350 ms / 3.591 TFLOP/s。

1024³ 提升很强，但大矩阵下降到 3.59 TFLOP/s，表明 DRAM 层面的 block 数据复用
仍不足；这触发 v8.3 扩大 BM。

## 6. v8.3：128×128 最终 tile

### 假设

BM 64→128 后，每个 block 加载更多 A，但对同一 B tile 计算两倍输出；理论
global input 算术强度从约 42.7 提到 64 FLOP/byte。8 个 warps 改为：

```text
warp grid: 4 rows × 2 columns
per warp:  2 × 4 WMMA accumulator fragments
```

代价是 8 个 FP32 accumulator fragments 将主 kernel 提到 115 registers/thread，
理论 occupancy 降到 33.33%。

### 结果与选择

1024³ 为 0.351360 ms / 6.112 TFLOP/s，比 v8.2 再快 1.34×。4096³ 短测为
26.510080 ms / 5.184 TFLOP/s，比 v8.2 的 3.591 TFLOP/s 快约 1.44×。

低 occupancy 没有抵消更高数据复用，且无 spill，因此选择 v8.3 作为最终主路径。
这与 FP32 v6 的结论一致：occupancy 是资源结果，不是独立优化目标。

## 11. Nsight Compute：v7 与最终 v8.3

1024³ 稳态 kernel：

| 指标 | v7 | v8.3 | 变化/解释 |
|---|---:|---:|---|
| Duration | 2.26 ms | 359.04 us | -84.1% |
| Memory throughput | 98.21% | 88.74% | 不再由 L1 global load 完全主导 |
| L1/TEX throughput | 99.76% | 44.85% | shared 复用显著减少 L1/TEX 压力 |
| L2 throughput | 53.63% | 88.74% | 最终主要供数层级 |
| Compute throughput | 17.32% | 37.97% | Tensor pipeline 37.7% |
| Issue slots busy | 11.56% | 38.46% | 3.33× |
| No eligible warp | 88.43% | 61.59% | -26.84 pp |
| Warp cycles / instruction | 101.19 | 10.26 | -89.9% |
| Executed instructions | 8,339,456 | 4,280,320 | -48.7% |
| Global excessive sectors | 8,388,608 | 5,224,288 | -37.7% |
| Registers / thread | 40 | 115 | 8 accumulators的代价 |
| Static shared / block | 0 | 20.99 KiB | 双 buffer + skew |
| Achieved occupancy | 97.56% | 33.09% | 寄存器限制为 2 blocks/SM |

v8.3 虽然 occupancy 大幅下降，但 shared 复用、skew、更多 accumulator fragments 和
cp.async 将 warp 指令间隔降低近 90%，Tensor pipeline 利用率翻倍以上。

最终 NCU 仍指出两项瓶颈：5,224,288 个 global excessive sectors（约 31%）和
8,668,352 个 shared excessive wavefronts（约 45%）；L2 throughput 已达 88.74%，
115 registers 又限制 occupancy。后续优化需要更精细的 ldmatrix/shared swizzle 或
不同输出 store 布局，而不是继续简单扩大 tile。

## 12. 稳定性与停止结论

4096³ 独立启动 5 次，每次 warmup 5、repeat 15：

```text
26.453568, 26.501535, 26.461824, 26.450624, 26.480415 ms
```

最大/最小跨度约 **0.19%**，远低于 3%。主结果使用此前正式全形状测试的
26.504704 ms，不从五次中挑最快值。

v8 完成了 baseline/final 正确性、常用与非对齐尺寸、异步同步审计、稳定性、
小版本负优化和最终瓶颈说明。当前冻结的 FP16 公开结果为：4096³
5.185 TFLOP/s、相对 v7 加速 5.32×、达到同口径 FP16 cuBLAS 的 64.29%。

按用户要求，GEMM 阶段在 v8 提交后暂停，等待审阅确认，不自动进入 Attention。
