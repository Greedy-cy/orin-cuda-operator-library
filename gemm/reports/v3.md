# GEMM v3：float4 加载、写回与标量回退

## 1. 优化与演进边界

v2 的 NCU 指出 global store 每个 32-byte sector 平均只利用 8 bytes。v3 保持
`64×64×16` block tile、256 线程和每线程 `4×4` 累加器不变，只重写数据搬运：

- A tile：256 个线程各搬一个 `float4`；
- B tile：256 个线程各搬一个 `float4`；
- C 写回：每个线程每行用一个 `float4` 写相邻 4 个输出；
- 仅当 `M%64==0, N%64==0, K%16==0` 时进入向量化主路径；
- 其他形状编译期分离到 v2 等价的标量补零/边界写回 kernel。

cudaMalloc 返回满足向量访问的基地址；主路径的 leading dimensions、block/tile
偏移均保证 16-byte 对齐。标量回退避免尾部越界，也让任意正尺寸继续可用。

同一算子已出现三个完整版本，因此从 v3 起按计划提取 `gemm_common.h`，只包含
GEMM 的参数解析、cuBLAS reference、验证和 CUDA Event median 计时。v0–v2
保持原文件不变；公共头不改变 v3 kernel 或测量口径。

`violations=0`；4096³ 最大绝对误差 `2.3e-5`。

## 4. LLM skinny-M 形状

固定 `K=N=4096`：

|---:|---|---:|---:|---:|---:|---|
| 1 | scalar fallback | 2.942208 ms | 11.405 GFLOP/s | 1.00× | 24.80% | PASS |
| 16 | scalar fallback | 3.161056 ms | 169.839 GFLOP/s | 0.98× | 42.32% | PASS |
| 128 | float4 | 4.438880 ms | 967.579 GFLOP/s | **1.37×** | **86.96%** | PASS |
| 512 | float4 | 17.354143 ms | 989.958 GFLOP/s | 1.35× | 73.25% | PASS |
| 1,024 | float4 | 34.577538 ms | 993.701 GFLOP/s | 1.35× | 73.40% | PASS |

M=128 时 custom 达到 cuBLAS 的 86.96%，但 M=1/16 的问题没有被向量化解决：
它们仍因 64-row tile 的无效计算而回退到低性能。该差异继续作为未来 dispatcher
引入 small-M 专用 kernel 的依据。

## 7. Nsight Compute：NCU 建议是否兑现

1024³ 的向量化稳态 kernel：

| 指标 | v2 | v3 | 变化/解释 |
|---|---:|---:|---|
| Duration | 2.99 ms | 2.20 ms | -26.4% |
| Roofline FP32 peak | 35% | 47% | +12 pp |
| Memory throughput | 66.75% | 86.28% | 搬运指令减少后有效供数更集中 |
| Compute throughput | 64.17% | 57.64% | 当前 SOL 受 L1/TEX 86.4% 先限制 |
| Issue slots busy | 64.41% | 57.73% | 向量指令减少非 FMA 发射数量 |
| No eligible warp | 35.79% | 42.26% | 仍受 64-register occupancy 与加载等待制约 |
| Executed instructions | 61,728,768 | 41,025,536 | **-33.5%** |
| Registers / thread | 64 | 64 | 不变 |
| Achieved occupancy | 64.53% | 64.23% | 不变 |

v2 的 uncoalesced global store/excessive-sector 警告在 v3 中消失。性能提升远高于
v2 报告中仅针对 store sector 的约 8% 局部估算，是因为 v3 同时将每轮 A/B 的
标量加载合并为 `float4`，总执行指令减少三分之一。寄存器、shared memory 和
occupancy 基本不变，因而收益可以归因于向量化数据搬运，而不是资源配置变化。

新的限制是 L1/TEX throughput 86.42%、64 registers/thread 将理论 occupancy
限制在 66.67%，调度器仍有 42.26% 周期无 eligible warp。下一步需要检验通过
双缓冲重叠 tile load 与 FMA 是否能隐藏等待，以及额外 buffer/寄存器是否反而
降低 occupancy。

## 8. 下一步

v4 做同步式双缓冲实验：保留 v3 的向量化加载与计算 tile，增加两份 shared tile，
尝试把“下一 tile 的 global load”与“当前 tile 的计算”在软件流水中交错。该版本
重点记录资源代价和可能的负优化；真正的 `cp.async` 留给 v5，避免把同步双缓冲
与硬件异步拷贝混在同一结论中。
