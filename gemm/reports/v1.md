# GEMM v1：16×16 shared-memory tiling

## 1. 单一改动

v1 保持 v0 的 `16×16` block 和“一线程计算一个输出”，只把 K 维切为长度 16
的 tile。每轮由 256 个线程协作加载：

```text
shared A tile: [16,16]
shared B tile: [16,16]
```

同步后每个线程从 shared memory 读取一行 A tile 和一列 B tile，完成 16 次 FMA。
这样同一 A/B 元素最多被 block 内 16 个输出复用。K 尾部显式补零；所有线程都
无条件经过 tile 前后的两次 `__syncthreads()`，避免非对齐 block 死锁。

本版没有引入 thread coarsening、寄存器分块、向量化或双缓冲，以便单独测量
shared-memory 数据复用的作用。

## 2. 环境与测量口径

| 项目 | 值 |
|---|---|
| GPU | Jetson Orin Nano Super，8 SM，sm_87 |
| CUDA / cuBLAS | 12.6 / 12.6，cuBLAS pedantic FP32 |
| 锁频 | MAXN_SUPER，GPU 1020 MHz，EMC 3199 MHz |
| 编译 | `-O3 -lineinfo -std=c++17 -arch=sm_87 -lcublas` |
| 计时 | warmup 5，运行 15 次取 median |
| 正确性 | cuBLAS reference；逐元素 `atol=1e-3, rtol=1e-3` |

运算量按 `2*M*N*K`，计时不包含内存分配、传输和正确性检查。v0/v1 使用同一
随机种子、参考实现和计时方式。

## 3. 方阵与非对齐尺寸

| M | N | K | v1 median | v1 | 相对 v0 | cuBLAS | cuBLAS 占比 | 结果 |
|---:|---:|---:|---:|---:|---:|---:|---:|---|
| 37 | 65 | 1,003 | 0.047968 ms | 100.576 GFLOP/s | 1.22× | 94.463 GFLOP/s | 106.47% | PASS |
| 1,024 | 1,024 | 1,024 | 8.730336 ms | 245.979 GFLOP/s | 1.47× | 1,305.798 GFLOP/s | 18.84% | PASS |
| 2,048 | 2,048 | 2,048 | 70.250626 ms | 244.551 GFLOP/s | 1.44× | 1,341.037 GFLOP/s | 18.24% | PASS |
| 4,096 | 4,096 | 4,096 | **563.534180 ms** | **243.888 GFLOP/s** | **1.43×** | **1,354.928 GFLOP/s** | **18.00%** | PASS |

4096³ 相比 v0 从 805.372 ms 降至 563.534 ms，证明显式 block 内复用有效。
从 1024³ 到 4096³，v1 维持 244–246 GFLOP/s，结果具有稳定的尺寸趋势。

非对齐形状最大绝对误差为 `2e-6`，4096³ 为 `2.3e-5`；所有测试均
`violations=0`。小型非对齐形状超过 cuBLAS 只反映两者固定开销不同，不作为
主性能结论。

## 4. LLM skinny-M 形状

固定 `K=N=4096`：

| M | v1 median | v1 | 相对 v0 | cuBLAS 占比 | 结果 |
|---:|---:|---:|---:|---:|---|
| 1 | 2.231104 ms | 15.039 GFLOP/s | **0.85×** | 32.64% | PASS |
| 16 | 2.315744 ms | 231.835 GFLOP/s | 1.42× | 46.82% | PASS |
| 128 | 17.726015 ms | 242.297 GFLOP/s | 1.43× | 21.76% | PASS |
| 512 | 70.516930 ms | 243.628 GFLOP/s | 1.43× | 18.03% | PASS |
| 1,024 | 140.950943 ms | 243.771 GFLOP/s | 1.43× | 18.02% | PASS |

`M=1` 比 v0 慢约 17%，原因是每个 `16×16` block 只有一行线程产生有效输出，
但 256 个线程仍要协作加载、执行同步，并加载 15 行最终无用的 A tile 数据。
因此通用 tiled SGEMM 不应被简历数字掩盖为所有 LLM 形状都适用；后续 dispatcher
需要将 GEMV/small-M 与大 M 路径分开。

## 5. Sanitizer

在 `M=37, N=65, K=1003` 上分别运行 memcheck 和 synccheck，二者均为：

```text
ERROR SUMMARY: 0 errors
correct=PASS
```

这验证了 M/N/K 三个非对齐尾部的补零、边界写回，以及每轮 tile 两个 block 同步
点。性能报告使用未插桩的普通运行结果。

## 6. Nsight Systems

1024³、warmup 2、repeat 3；custom 和 cuBLAS 各 6 个实例：

| Kernel | 实例 | Median | GPU kernel 时间占比 |
|---|---:|---:|---:|
| `sgemm_tiled_kernel` | 6 | 8.727456 ms | 84.2% |
| `ampere_sgemm_128x64_nn` | 6 | 1.632624 ms | 15.8% |

nsys 中值与 CUDA Event 的 8.730336 ms 一致。v1 仍是单 kernel，未引入额外 launch
或中间缓冲；提升确实来自 kernel 内的 tiled 数据复用。

## 7. Nsight Compute：与 v0 对照

1024³ 的一次稳态 kernel：

| 指标 | v0 | v1 | 变化 |
|---|---:|---:|---:|
| Duration | 12.97 ms | 8.74 ms | -32.6% |
| Memory throughput | 95.86% | 91.45% | -4.41 pp |
| L1/TEX throughput | 96.00% | 91.56% | -4.44 pp |
| Compute throughput | 63.86% | 71.09% | +7.23 pp |
| Issue slots busy | 44.42% | 49.23% | +4.81 pp |
| No eligible warp | 55.58% | 50.75% | -4.83 pp |
| Long scoreboard | 16.0 cycles，59.7% | 10.1 cycles，41.7% | 等待占比下降 18.0 pp |
| Executed instructions | 186,712,064 | 139,526,144 | -25.3% |
| Registers / thread | 40 | 37 | -3 |
| Static shared / block | 0 | 2.05 KB | +2.05 KB |
| Achieved occupancy | 99.50% | 99.40% | 基本不变 |

数据复用同时减少了约四分之一执行指令，并明显缩短 global/L1TEX scoreboard
等待；compute throughput 上升，说明优化方向生效。但 v1 的 occupancy 已为
99.4%，且 memory throughput 仍达 91.45%，不能靠增加驻留 warp 解决剩余差距。

每 16 次 FMA，线程仍需参与两次 tile load、两次 block barrier，并只维护一个
累加器。下一步应提高“每次同步和每份输入数据对应的输出数量”。

## 8. 下一步

v2 使用更大的 block output tile 和 thread coarsening：每线程在寄存器中维护多个
输出，使加载到 shared memory 的 A/B 数据产生更多 FMA，并摊薄同步与地址计算。
v2 仍使用标量、同步式 tile load；`float4` 和流水化分别留给 v3、v4/v5。
