# Softmax v3：warp-per-row / block-per-row dispatch

## 1. 优化假设

v2 在 `cols=128` 时，每行只有 32 个 `float4` 元素，实际只有一个 warp 执行
元素 load/exp/store，其余 7 个 warp 只参与 block reduction。v2 的短行 ncu
进一步显示 55.6% 的发射间隔在 CTA barrier 等待。

v3 对 `cols<=128` 使用一 warp 一行、一个 256 线程 block 同时处理 8 行；所有
规约仅用 warp shuffle，不使用 shared memory 或 `__syncthreads()`。更长行完整
保留 v2 block kernel。

## 2. 正确性与性能

| Rows | Cols | Path | v2 Median | v3 Median | 相对 v2 | 正确性 |
|---:|---:|---|---:|---:|---:|---|
| 1 | 32 | warp | 0.008512 ms | 0.008448 ms | 1.01× | PASS |
| 1 | 1,024 | block | 0.008192 ms | 0.008832 ms | 0.93× | PASS |
| 128 | 128 | warp | 0.013696 ms | **0.009680 ms** | **1.41×** | PASS |
| 128 | 1,024 | block | 0.018064 ms | 0.017968 ms | 1.01× | PASS |
| 128 | 8,192 | block | 0.167168 ms | 0.164176 ms | 1.02× | PASS |
| 4,096 | 128 | warp | 0.222080 ms | **0.061840 ms** | **3.59×** | PASS |
| 4,096 | 1,024 | block | 0.426080 ms | 0.426432 ms | 1.00× | PASS |
| 4,096 | 8,192 | block | 5.111280 ms | 5.096704 ms | 1.00× | PASS |

`4096×128` 相对 v0 的 0.323488 ms 达到 **5.23×** 加速，有效 I/O 带宽从
12.97 GB/s 提升到 67.83 GB/s。长行路径保持不变，没有用短行优化破坏主路径。

## 3. Nsight Systems

`4096×128` 的三个 warp kernel 实例 median 为 **0.058272 ms**，与独立
benchmark 0.061840 ms 接近。

## 4. Nsight Compute：短行 v2 与 v3

| 指标 | v2 block-per-row | v3 warp-per-row | 变化 |
|---|---:|---:|---:|
| Grid | 4096 blocks | 512 blocks（每 block 8 行） | launch 工作聚合 |
| Memory throughput | 39.49% | **84.70%** | 2.15× |
| L2 throughput | 22.62% | **84.70%** | 显著提高 |
| Compute throughput | 46.84% | 46.01% | 接近 |
| No eligible warp | 52.51% | 51.67% | 接近 |
| 主要 stall | **Barrier 12.6 cycles / 55.6%** | L1TEX 10.6 cycles / 51.8% | barrier 被消除 |
| Achieved occupancy | 90.41% | 82.15% | 降低但性能更高 |
| Registers / thread | 32 | 22 | 降低 |
| Executed instructions | 3,289,088 | **913,408** | 下降 72.2% |
| Dynamic shared / block | 32 bytes | 0 | 消除 |

v3 的收益不是来自更高 occupancy，而是让每个 warp 都独立完成一行，消除了
跨 warp barrier 和 7/8 warp 的工作不均衡。该结果再次说明 occupancy 不是
孤立的优化目标。

## 5. 下一步

v4 针对资源允许的行长把一行数据保存在寄存器中：

- `cols<=128`：每 lane 最多缓存 4 个标量；
- 对齐且 `128<cols<=1024`：每线程缓存一个 `float4`；
- 更长或非对齐行继续使用 v3 block path。

缓存将消除求 max 后的第二次输入读取，并让指数值在 sum reduction 期间留在
寄存器，最终只写一次归一化结果。该版本以降低真实全局流量为目标，而不是
继续调整规约方式。
