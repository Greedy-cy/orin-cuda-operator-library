# Softmax v1：warp shuffle reduction

## 1. 优化假设

v0 的 max 和 sum 各执行一套 256 线程 shared tree reduction，每套包含初始同步
和 8 个规约阶段。v1 保持全局内存访问、指数计算和 launch 配置不变，只将规约
改为两级 warp shuffle：warp 内 shuffle，warp leader 写 8 个 shared 值，第一个
warp 完成最终规约。

## 2. 同步变化

- v0：max/sum 各约 9 次全 block 同步。
- v1：max 使用 2 次、sum 使用 3 次全 block 同步；额外的一次用于隔离复用
  shared memory 的 max/sum 两阶段。
- dynamic shared memory：从 1,024 bytes 降至 32 bytes。

## 4. Nsight Systems

`4096×1024` 的六个 kernel 实例 median 为 **0.592064 ms**，v0 为
0.678048 ms，nsys 对应加速 1.15×，与独立 benchmark 趋势一致。

## 5. Nsight Compute 对比

| 指标 | v0 | v1 | 变化 |
|---|---:|---:|---:|
| Compute throughput | 59.52% | 49.40% | reduction 指令减少 |
| Memory throughput | 58.67% | **67.85%** | 内存占比上升 |
| L1/TEX throughput | 50.50% | 28.50% | shared/L1TEX 压力下降 |
| Issue slots busy | 60.16% | 49.79% | 指令减少 |
| No eligible warp | 40.08% | 50.29% | 内存等待占比上升 |
| L1TEX scoreboard stall | 8.8 cycles | 12.8 cycles | 内存成为更突出限制 |
| Registers / thread | 18 | 23 | shuffle 临时值增加 |
| Achieved occupancy | 97.51% | 97.01% | 基本不变 |
| Executed instructions | 12,845,056 | **9,330,688** | 下降 27.4% |

v1 明确减少了规约和 shared-memory 指令，使 kernel 从 Compute/Memory 均衡转为
Memory 更重。occupancy 几乎没有变化，性能收益来自减少同步和指令，而不是
提高并发度。

## 6. Sanitizer 追溯

max/sum 的二级规约最初复用了同一 shared 数组，但缺少两阶段之间的 block
同步。racecheck 在后续 v4 中将其定位为 WAR 竞争；v1 已在 sum 规约入口增加
同步。`17×1024` 复验得到 `0 hazards` 与 `correct=PASS`，本页数据均为修复后
重采。

## 7. 下一步

v2 保留 warp shuffle 规约，尝试对输入、指数中间值和归一化使用 `float4`
向量化。目标不是减少实际 DRAM 字节，而是减少标量 load/store 和循环指令。
Reduce v4 已证明向量 load 可能损害 MLP，因此 Softmax v2 必须以实测决定去留。
