# Softmax v1：warp shuffle reduction

## 1. 优化假设

v0 的 max 和 sum 各执行一套 256 线程 shared tree reduction，每套包含初始同步
和 8 个规约阶段。v1 保持全局内存访问、指数计算和 launch 配置不变，只将规约
改为两级 warp shuffle：warp 内 shuffle，warp leader 写 8 个 shared 值，第一个
warp 完成最终规约。

## 2. 同步变化

- v0：max/sum 各约 9 次全 block 同步。
- v1：max/sum 各 2 次全 block 同步。
- dynamic shared memory：从 1,024 bytes 降至 32 bytes。

| 1 | 1,024 | 0.010800 ms | 0.009760 ms | 1.11× | 0.839344 GB/s | PASS |
| 128 | 128 | 0.017744 ms | 0.013504 ms | 1.31× | 9.706161 GB/s | PASS |
| 128 | 1,024 | 0.024320 ms | 0.021248 ms | 1.14× | 49.349398 GB/s | PASS |
| 128 | 8,192 | 0.217776 ms | 0.214640 ms | 1.01× | 39.082223 GB/s | PASS |
| 4,096 | 128 | 0.323488 ms | **0.213600 ms** | **1.51×** | 19.636254 GB/s | PASS |

极端 logits `4×1003` 同样通过。收益随每行数据量增加而下降，证明规约同步
在短行中占比高，而长行更多时间消耗在 exp 和内存访问。

## 4. Nsight Systems

`4096×1024` 的三个 kernel 实例 median 为 **0.596384 ms**，v0 为
0.689984 ms，nsys 对应加速 1.16×，与独立 benchmark 趋势一致。

## 5. Nsight Compute 对比

| 指标 | v0 | v1 | 变化 |
|---|---:|---:|---:|
| Compute throughput | 60.12% | 49.45% | reduction 指令减少 |
| Memory throughput | 59.50% | **67.30%** | 内存占比上升 |
| L1/TEX throughput | 50.96% | 28.25% | shared/L1TEX 压力下降 |
| Issue slots busy | 60.83% | 49.62% | 指令减少 |
| No eligible warp | 39.16% | 50.50% | 内存等待占比上升 |
| L1TEX scoreboard stall | 8.8 cycles | 12.8 cycles | 内存成为更突出限制 |
| Registers / thread | 18 | 23 | shuffle 临时值增加 |
| Achieved occupancy | 97.92% | 97.12% | 基本不变 |
| Executed instructions | 12,812,288 | **9,297,920** | 下降 27.4% |

v1 明确减少了规约和 shared-memory 指令，使 kernel 从 Compute/Memory 均衡转为
Memory 更重。occupancy 几乎没有变化，性能收益来自减少同步和指令，而不是
提高并发度。

## 6. 下一步

v2 保留 warp shuffle 规约，尝试对输入、指数中间值和归一化使用 `float4`
向量化。目标不是减少实际 DRAM 字节，而是减少标量 load/store 和循环指令。
Reduce v4 已证明向量 load 可能损害 MLP，因此 Softmax v2 必须以实测决定去留。
