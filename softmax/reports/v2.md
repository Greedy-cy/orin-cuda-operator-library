# Softmax v2：float4 向量化与标量回退

## 1. 优化假设

v1 已将规约成本显著降低，并在主形状转为内存主导。v2 对 `cols % 4 == 0`
的行使用 128-bit `float4` 读取、写入和归一化，减少标量内存及循环指令；非 4
对齐行完整回退到 v1 的标量路径。

与 Reduce v4 不同，Softmax 每个元素还包含 max、exp、sum 和 normalize，减少
指令可能比保持多条独立标量 load 更重要，因此需要单独验证。

## 2. 正确性与性能

| Rows | Cols | v1 Median | v2 Median | 相对 v1 | v2 有效 I/O | 正确性 |
|---:|---:|---:|---:|---:|---:|---|
| 1 | 32 | 0.008592 ms | 0.008592 ms | 1.00× | 0.029795 GB/s | PASS |
| 1 | 1,024 | 0.009872 ms | 0.008736 ms | 1.13× | 0.937729 GB/s | PASS |
| 128 | 128 | 0.013632 ms | 0.013904 ms | 0.98× | 9.426928 GB/s | PASS |
| 128 | 1,024 | 0.021360 ms | 0.017808 ms | 1.20× | 58.882301 GB/s | PASS |
| 128 | 8,192 | 0.217248 ms | 0.170432 ms | 1.27× | 49.219677 GB/s | PASS |
| 4,096 | 128 | **0.214576 ms** | 0.225840 ms | **0.95×** | 18.572015 GB/s | PASS |
| 4,096 | 1,024 | 0.596368 ms | **0.426496 ms** | **1.40×** | **78.674670 GB/s** | PASS |
| 4,096 | 8,192 | 6.126560 ms | 5.032816 ms | 1.22× | 53.337030 GB/s | PASS |

`4×1003` 极端 logits 走标量回退，正确性通过，median 为 0.010848 ms。

向量化对 1K 和 8K 行长有明显收益，但 `cols=128` 略慢。原因是每行只有
32 个 `float4`，一个 warp 已能读完；当前仍启动 256 线程，其他 7 个 warp
只参与规约，没有承担元素工作。

## 3. Nsight Systems

`4096×1024` 的六个 kernel 实例 median 为 **0.421840 ms**，v1 为
0.592064 ms，对应 1.40× 加速，与独立 benchmark 一致。

## 4. Nsight Compute 对比

| 指标 | v1 | v2 | 变化 |
|---|---:|---:|---:|
| Memory throughput | 67.85% | **93.13%** | 接近 L2 上限 |
| Compute throughput | 49.40% | 41.29% | 相对占比下降 |
| Issue slots busy | 49.79% | 41.52% | 指令减少 |
| No eligible warp | 50.29% | 58.47% | 更内存受限 |
| L1TEX scoreboard stall | 12.8 cycles | 13.8 cycles | 近似 |
| Registers / thread | 23 | 32 | 四分量临时值增加 |
| Achieved occupancy | 97.01% | 95.31% | 基本不变 |
| Executed instructions | 9,330,688 | **5,644,288** | 下降 39.5% |

v2 的性能提升来自指令数下降和更高的内存吞吐；L2 throughput 达到 93.13%，
ncu 已提示可用内存性能超过 80%。主形状继续通过全局流量优化获得大幅收益会
比较困难。

## 5. Sanitizer 追溯

与 v1 相同，sum 规约入口增加 block 同步以安全复用 shared 数组。修复后
racecheck 在 `17×1024` 报告 `0 hazards`。短行 `4096×128` 的复采显示 CTA
barrier stall 为 12.7 / 22.8 cycles（55.8%），进一步支持 v3 改用
warp-per-row，而不是继续调整向量宽度。

## 6. 下一步

v3 不再修改主形状的数据路径，而是增加 shape-aware dispatch：

- `cols <= 128`：一个 warp 处理一行，一个 block 同时处理 8 行；
- `cols > 128`：保留 v2 的一个 block 处理一行。

这会解决短行中 7/8 warp 不承担元素工作的浪费，并验证“不同形状需要不同
并行粒度”，而不是寻找一个覆盖所有行长的单一配置。
