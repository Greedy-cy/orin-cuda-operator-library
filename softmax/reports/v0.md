# Softmax v0：shared-memory tree reduction baseline

## 1. 实验目的

建立数值稳定、支持任意行长的 FP32 Softmax baseline。一行对应一个 256 线程
block，分别用 shared-memory tree reduction 求 max 和 sum。指数中间值写入
全局输出，再读回进行 normalize。

## 2. 环境与计时

| 项目 | 值 |
|---|---|
| GPU | Jetson Orin Nano Super，8 SM，sm_87 |
| CUDA | 12.6 |
| 功耗/时钟 | MAXN_SUPER，GPU 1020 MHz，EMC 3199 MHz |
| 编译 | `-O3 -lineinfo -std=c++17 -arch=sm_87` |
| 计时 | warmup 10 次，CUDA Event 计时 30 次取 median |

有效 I/O 带宽按每元素最小的 1 次输入读取和 1 次输出写入（8 bytes）计算，
用于跨版本统一比较；v0 实际还包含指数中间值的全局写回和读回。

## 3. 正确性

CPU 参考使用 double 计算指数和归一化。所有测试均满足：

- 最大绝对误差不超过 `2e-5`；
- 每行输出和与 1 的误差不超过 `2e-5`；
- `rows=4, cols=1003, logits∈[-1000,1000]` 极端输入通过；
- 非 256 对齐列数通过。

|---:|---:|---:|---:|---|
| 1 | 32 | 0.009264 ms | 0.027634 GB/s | PASS |
| 1 | 1,024 | 0.010544 ms | 0.776935 GB/s | PASS |
| 128 | 128 | 0.017680 ms | 7.413574 GB/s | PASS |
| 128 | 1,024 | 0.024464 ms | 42.862001 GB/s | PASS |
| 128 | 8,192 | 0.214336 ms | 39.137652 GB/s | PASS |
| 4,096 | 128 | 0.328384 ms | 12.772560 GB/s | PASS |
| 4,096 | 1,024 | **0.667824 ms** | **50.244421 GB/s** | PASS |
| 4,096 | 8,192 | 6.235888 ms | 43.046869 GB/s | PASS |

短行 `cols=128` 中每个 block 只有一半线程读取有效元素，且仍执行两套完整的
256 线程 tree reduction，因此带宽明显偏低。长行性能下降则来自更多循环、
exp 计算和指数中间值的全局往返。

## 5. Nsight Systems

`4096×1024` 的六个 kernel 实例 median 为 **0.678048 ms**，与独立 benchmark
的 0.667824 ms 接近。时间线中只有一个 Softmax kernel，没有额外 device copy
进入计时区间。

| Executed instructions | 12,845,056 |

ncu 判断 Compute 和 Memory 基本均衡。occupancy 已接近 100%，因此提高 block
数量或继续追求 occupancy 不是重点。当前可以同时减少的工作有：

1. shared tree reduction 及两阶段隔离的 19 次全 block 同步；
2. 最后一个 warp 仍通过 shared memory 通信；
3. `exp(x-max)` 先写入全局内存、随后读回归一化。

## 7. Sanitizer 追溯

在 v4 开发阶段，racecheck 发现 max 与 sum 两阶段复用 shared memory 时存在
write-after-read 竞争。v0 在写入 sum 的线程局部值前增加一次 `__syncthreads()`，
确保所有 warp 已经读取 `row_max`。修复后的命令：

```bash
compute-sanitizer --tool racecheck --error-exitcode=1 \
  ./build/softmax_v0 --rows=17 --cols=1024 --warmup=0 --repeat=1
```

结果为 `0 hazards`、`correct=PASS`。本报告性能与 Nsight 数据均已用修复后的
源码重采，避免隐藏竞态被正常调度偶然掩盖。

## 8. 下一步

v1 只处理第一项：max 和 sum 的 reduction tail 改用 warp shuffle，每个 block
先把各 warp 结果写入 shared memory，再由第一个 warp 完成最终规约。输入读取、
指数写回和归一化保持不变，用来单独量化规约同步的成本。
