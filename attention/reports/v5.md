# Attention v5：vectorized cp.async K/V 双缓冲

## 1. 来自 v3/v4 的判断

v3 的 tile 扫描将主形状降到 43.216 ms。v4 通过双 key accumulator 减少短序列
指令，但 D128 长序列没有收益，说明下一步应处理每轮 K/V tile 的加载与 barrier，
而不是继续扩大在线状态分组。

v5 回到 v3 的逐 key online-softmax 数学，只改变数据搬运：

- K/V 每次以 16-byte `cp.async.cg.shared.global` 加载；
- 两份 K shared buffer 和两份 V shared buffer；
- `commit_group` 后预取下一 tile；
- `wait_group<1>` 保留一个在途 group，末 tile `wait_group<0>`；
- 计算当前 buffer 时下一 buffer 在途；
- D64 使用 BM16,BN32、32 KiB shared；
- D128 使用 BM32,BN32、64 KiB shared；
- S/D 不满足对齐条件时走无 shared 的 scalar online fallback。

D64 从 v3 的 BN64 改为 BN32，是为 double buffer 将 shared 保持在 32 KiB；D128
的 1024-thread block 原本就只能驻留一个 block，shared 从 32 增至 64 KiB 没有
进一步降低 block residency。

## 2. 正确性与 fallback

| 路径 | 形状 | 最大绝对误差 | 结果 |
|---|---|---:|---|
| scalar fallback | `B1,H2,S37,D71,causal=1` | `3.73e-8` | PASS |
| cp.async | `B1,H2,S64,D128,extreme=1` | `9.84e-7` | PASS |
| cp.async | `B1,H8,S128,D64,non-causal` | `9.31e-9` | PASS |
| cp.async | `B1,H8,S128,D128,causal` | `2.98e-8` | PASS |

fallback 不是为了性能，而是保证任意 S 和 `1<=D<=128` 都有正确路径。主路径要求
D=64/128 且 S 为 32 的倍数，满足首期 LLM 形状。

## 3. sanitizer 与资源

`B1,H1,S64,D128,causal=1` 的 64 KiB 双缓冲路径：

- memcheck：0 errors；
- racecheck：0 hazards；
- synccheck：0 errors；
- CPU double reference：PASS。

`B1,H1,S37,D71` fallback memcheck 也是 0 errors。该组合覆盖 async group 等待、
双 buffer 翻转、causal 提前停止与标量边界。

ptxas：cp.async D64/D128 specialization 均为 44 registers/thread、0 spill、1
barrier；fallback 为 40 registers、0 spill、0 barrier。

|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|

| 1 | 8 | 128 | 128 | 1 | 0.270784 | **0.246656 ms** | 272.075 GFLOP/s | 1.10x | 5.92x |

其余 FP32 路径选择 v5。

## 5. Nsight Systems

S=128,D=64 单 kernel median：

| 版本 | Median |
|---|---:|
| v3 synchronous tiled | 0.414480 ms |
| v4 paired update | **0.385264 ms** |
| v5 cp.async double buffer | 0.393968 ms |

v5 相对相同逐 key数学的 v3 快 5.2%；短序列仍不及 v4 paired update。正式 Event
分别为 0.419008/0.389920/0.398944 ms，与 nsys 排序一致。

## 6. Nsight Compute

同一 S=128,D=64；v5 为 BM16,BN32，v3 为 BM32,BN32，因此指标反映最终选择而
非完全相同 launch shape：

| 指标 | v3 | v5 |
|---|---:|---:|
| Duration | 422.05 us | **397.50 us** |
| Compute throughput | 86.37% | 86.80% |
| Memory throughput | 63.03% | 66.41% |
| L1 hit rate | 11.27% | **0%**（cp.async.cg 绕过 L1 缓存策略） |
| L2 hit rate | 75.98% | 83.11% |
| Issue slots busy | 87.11% | 87.35% |
| Warp cycles/instruction | 9.19 | **8.68** |
| Registers/thread | 40 | 44 |
| Achieved occupancy | 66.72% | 63.21% |

性能提升不是 occupancy 增加；v5 occupancy 反而略低。async copy、双 buffer 与更短
warp 指令间隔覆盖了加载等待。NCU 仍指出 active lanes 22.85、predicated-on 18.60，
说明逐 key lane0 状态更新与 D fragment 控制仍有并行度损失。

## 7. 决策与下一步

v5 是当前 FP32 长序列 final candidate。v6 转入 FP16 Tensor Core 路线：Q/K/V
使用 FP16，QK/PV 乘加用 WMMA，online-softmax 的 maximum/sum/rescale 仍为 FP32。
由于 dtype 和参考库 math mode 改变，v6 起单独建表，不能声称相对 FP32 cuDNN 的
比例或把 TFLOP/s 与 v5 混为同一精度口径。
