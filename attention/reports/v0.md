# Attention v0：显式 score 三阶段基线

## 1. 目的与实现

v0 建立最小且可解释的 scaled dot-product attention：

```text
scores = Q * K^T / sqrt(D)
P      = stable_softmax(scores)
O      = P * V
```

数据布局为 FP32 `[B,H,S,D]`，score/probability 为 FP32 `[B,H,S,S]`。三个阶段
分别启动 CUDA kernel：

1. 每个线程计算一个 `(query,key)` dot product；
2. 每行一个单线程 block 串行执行 max、exp、sum 和 normalize；
3. 每个线程计算一个输出元素并沿 S 累加。

causal 模式在 QK 阶段将 `key_index > query_index` 写为 `-inf`。Softmax 在减去
行最大值后再取指数，避免大正数溢出。该版本故意不做 shared tiling、warp reduce
或融合，作为后续所有加速和显存下降的共同基线。

## 2. 环境与测量口径

| 项目 | 值 |
|---|---|
| GPU | Jetson Orin Nano Super，8 SM，sm_87 |
| CUDA | 12.6 |
| 锁频 | MAXN_SUPER，GPU 1020 MHz，EMC 3199 MHz |
| 编译 | `nvcc -O3 -lineinfo -std=c++17 -arch=sm_87` |
| 计时 | warmup 5；每次单独 CUDA Event；15 次取 median |
| FLOPs | dense 口径 `4*B*H*S*S*D` |
| 小尺寸参考 | CPU double precision |
| 通过阈值 | `abs_error <= 1e-4 + 1e-4*abs(reference)` |

causal 也报告 dense FLOPs，便于版本间使用固定分母比较。v0 的 causal QK 会跳过
被 mask 的 dot product，但 PV 仍扫描整行零概率，因此该数字不是“有效 causal
FLOPs”。

|---|---:|---:|---:|---|
| 1,2,32,64 | 0 | `1.40e-8` | `2.33e-7` | PASS |
| 1,2,37,71 | 1 | `2.98e-8` | `2.09e-7` | PASS |
| 1,8,128,64 | 0 | `8.38e-9` | `4.45e-7` | PASS |
| 1,8,128,128 | 1 | `2.98e-8` | `4.65e-7` | PASS |

`S=37,D=71` 专门覆盖非 tile、非向量对齐边界。较大形状不运行昂贵 CPU O(S²D)
参考，但逐元素检查输出有限值，并从 device 拷回全部 probability 验证每行和接近
1；S=2048 的最大行和误差为 `4.84e-6`。

```text

```

## 4. 正式性能

| B | H | S | D | causal | score buffer | Median | Dense 性能 |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 1 | 8 | 128 | 64 | 0 | 512 KiB | 1.332928 ms | 25.173 GFLOP/s |
| 1 | 8 | 128 | 128 | 1 | 512 KiB | 1.461408 ms | 45.921 GFLOP/s |
| 1 | 8 | 512 | 64 | 0 | 8 MiB | 21.170303 ms | 25.360 GFLOP/s |
| 1 | 12 | 1024 | 128 | 0 | 48 MiB | **237.440582 ms** | **27.133 GFLOP/s** |
| 1 | 12 | 1024 | 128 | 1 | 48 MiB | 134.412003 ms | 47.931 GFLOP/s |
| 1 | 8 | 2048 | 128 | 0 | 128 MiB | 632.985168 ms | 27.141 GFLOP/s |

非 causal 从 S=128 到 2048 始终约 25--27 GFLOP/s，说明它不是小尺寸 launch
overhead 的偶发现象。causal 因在上三角提前跳过 QK dot product 而更快，但仍保留
完整 score 缓冲和 PV 全扫描。

score/probability 仅这一项在 `B=1,H=12` 时随序列长度增长为：

| S | 显式 FP32 缓冲 |
|---:|---:|
| 128 | 768 KiB |
| 512 | 12 MiB |
| 1024 | 48 MiB |
| 2048 | 192 MiB |
| 4096 | 768 MiB |

这张表是后续 FlashAttention “不保存 S²” 显存收益的基准，不把 Q/K/V/O 固有存储
混入该数字。

## 5. Nsight Systems

形状 `B=1,H=8,S=128,D=64,causal=0`，warmup 2、repeat 3；包含正确性启动、
warmup 和 timed 共 6 组：

| kernel | 实例 | Median | GPU kernel 时间占比 |
|---|---:|---:|---:|
| `qk_kernel` | 6 | 1.085488 ms | **81.6%** |
| `softmax_serial_kernel` | 6 | 0.156752 ms | 12.1% |
| `pv_kernel` | 6 | 0.084224 ms | 6.4% |

结论：第一版应先修正 QK 数据映射，而不是直接优化只占 6.4% 的 PV。三次 launch
相对毫秒级 QK 不是主要开销，但 QK+Softmax 可以自然融合并减少一次 score 往返。

## 6. Nsight Compute：QK

同一形状的稳态 `qk_kernel`：

| 指标 | 值 | 解释 |
|---|---:|---|
| Duration | 1.09 ms | 与 nsys 对齐 |
| Memory throughput | 98.08% | memory path 饱和 |
| L1/TEX throughput | **98.41%** | 主要瓶颈 |
| L2 throughput | 1.76% | 大量读取在 L1 重放/命中 |
| Compute throughput | 6.03% | FMA 管线远未利用 |
| Issue slots busy | 4.24% | 每约 23.6 cycles 才 issue |
| No eligible warp | 95.75% | 虽有 94.83% achieved occupancy 仍供不上指令 |
| Warp cycles/instruction | 268.45 | 极高 |
| Registers/thread | 37 | 无寄存器压力证据 |

NCU 指出每线程平均只使用每个 32-byte sector 中 4 bytes；共 8,667,136 sectors
里 7,334,003（约 85%）是 excessive sectors，估计合并访问可带来 55.17% 的局部
改进。warp stall 中 LG throttle 平均 238.9 cycles，占指令间隔约 89.2%。

根因是相邻线程计算相邻 key column，但在 dot-product 的同一个 d 上读取地址相隔
`D*sizeof(float)`，不是连续地址。高 occupancy 无法掩盖这个访问模式。

## 7. 下一版本假设

v1 仍保留 `[B,H,S,S]`：

- 一个 block 处理一个 query row；
- 一个 warp 协作计算一个 key dot product，lane 沿 D 合并读取 Q/K；
- warp shuffle 规约 dot product；
- block shuffle/shared reduction 完成 max/sum；
- QK 与 Softmax 合为一个 kernel，结果仍写回 global；
- PV 暂不改变。

如果 v1 有效，NCU 应看到 L1/TEX 压力和 excessive sectors 显著下降，nsys 中 QK+
Softmax 总时长下降；显式 S² 缓冲仍存在，留给 v2 online softmax 单独解决。

cuDNN 对照暂不塞进 v0：旧目录的 legacy MHA 封装只支持非 causal、B=1，并使用
平均值计时。待第三个版本出现重复评测代码后，再提取本算子的 common header，
以同一 causal/dtype/median 口径加入 cuDNN，避免历史数字污染新基准。
