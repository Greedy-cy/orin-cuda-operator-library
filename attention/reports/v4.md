# Attention v4：双 key 累加器与合并 online 更新

## 1. 假设

v3 对每个 key 串行执行：dot reduction、`m_new`、两次 exp、O rescale 和 V 加权。
相邻 key 之间通过 `(m,l,O)` 形成长依赖链。

v4 每次处理两个相邻 key：

```text
dot0 = Q*K0, dot1 = Q*K1               // 两条独立 FMA 链
m_new = max(m, score0, score1)
alpha = exp(m-m_new)
beta0 = exp(score0-m_new)
beta1 = exp(score1-m_new)
l = alpha*l + beta0 + beta1
O = alpha*O + beta0*V0 + beta1*V1
```

相比两个逐 key 更新，旧 O 只 rescale 一次，alpha 从两次 exp 减为一次 exp；两个
dot accumulators 可交错调度。BM/BN dispatcher、shared K/V、FP32 dtype 和最终 O/l
保持不变。

## 2. 正确性

分组顺序改变会产生正常的 FP32 舍入差异：

| B,H,S,D | causal | extreme | 最大绝对误差 | 结果 |
|---|---:|---:|---:|---|
| 1,2,37,71 | 1 | 0 | `2.98e-8` | PASS |
| 1,2,65,128 | 0 | 1 | `9.97e-7` | PASS |
| 1,8,128,64 | 0 | 0 | `8.38e-9` | PASS |
| 1,8,128,128 | 1 | 0 | `3.73e-8` | PASS |

奇数 S、奇数 causal 可见长度和非整齐 D 均覆盖。`S=65,extreme=1` 验证最后单 key
分组和大幅 score 下的稳定性。

`B1,H1,S37,D71,causal=1`：memcheck 0 errors、racecheck 0 hazards、synccheck
0 errors，CPU double reference PASS。

## 3. 正式性能

| B | H | S | D | causal | v3 | v4 | v4/v3 | 决策 |
|---:|---:|---:|---:|---:|---:|---:|---:|---|
| 1 | 8 | 128 | 64 | 0 | 0.419008 | **0.389920 ms** | **1.075x** | 短序列保留 |
| 1 | 8 | 128 | 128 | 1 | 0.270784 | **0.268320 ms** | 1.009x | 不足 3% |
| 1 | 8 | 512 | 64 | 0 | 6.433344 | **6.241536 ms** | **1.031x** | D64 边界收益 |
| 1 | 12 | 1024 | 128 | 0 | **43.215839** | 43.506306 ms | **0.993x，负优化** | 使用 v3 |
| 1 | 12 | 1024 | 128 | 1 | 22.487841 | **22.379105 ms** | 1.005x | 不足 3% |
| 1 | 8 | 2048 | 128 | 0 | **115.086082** | 115.759842 ms | **0.994x，负优化** | 使用 v3 |

结论不能写成“v4 全面更快”：它对 S128,D64 有 7.5% 收益，对 S512,D64 刚超过
3%，但 D128 长序列没有收益。主要评估形状继续以 v3 为 FP32 baseline。

## 4. 资源

| 项目 | v3 | v4 |
|---|---:|---:|
| Registers/thread | 40 | 42 |
| Spill | 0 | 0 |
| Dynamic shared | 相同 | 相同 |
| Barrier | 1 | 1 |

多一个 dot 与 beta 状态只增加 2 registers，未 spill；1024-thread config 的理论
occupancy 仍为 66.67%。

## 5. Nsight Systems 与 Compute

S=128,D=64：nsys 单 kernel median 从 v3 `0.414480 ms` 降至 v4
`0.385264 ms`，快 7.58%，与 Event 结果一致。

| NCU 指标 | v3 | v4 | 变化 |
|---|---:|---:|---|
| Duration | 422.05 us | **393.54 us** | -6.8% |
| Executed instructions | 11,773,952 | **11,141,120** | -5.4% |
| Issue slots busy | 87.11% | 88.41% | +1.30 pp |
| Warp cycles/instruction | 9.19 | 9.02 | -1.8% |
| Active threads/warp | 23.33 | **24.67** | +5.7% |
| Predicated-on threads/warp | 19.23 | **23.54** | +22.4% |
| L1/TEX throughput | 63.56% | **49.35%** | 同样加载量下 kernel 更短/路径变化 |
| Registers/thread | 40 | 42 | 无 spill |

双 key 分组确实减少指令并改善 active lanes，不是测量噪声。但长序列中 K/V tile
加载、shared 访问、dot/PV 总乘加占比更大，减少部分 online 状态指令不足以覆盖
额外第二 accumulator/control 的代价。

NCU 的 shared store conflict 从 v3 的 4419 降到 3598，但仍约 1.2-way；下一版
优先改变 K/V 加载流水，而不是继续扩大 pair=4（后者会进一步增加寄存器和 causal
尾部控制）。

## 6. 决策

v4 作为条件优化和负优化证据保留：短序列 D64 可以采用，D128/S>=1024 退回 v3。
v5 将在 v3 的逐 key 稳定路径上增加 vectorized/cp.async double buffering，并分别
测量同步、寄存器、shared 和长序列收益；不把 v4 与 v5 同时叠加，以免无法归因。
