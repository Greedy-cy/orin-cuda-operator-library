# Attention v3：BM/BN 有限扫描与 dispatcher

## 1. 动机与控制变量

v2 已消除 S² global intermediate，但 `BM=8,BN=32` 在 non-causal 主形状比 v1
慢 5.8%。NCU 显示 v2 compute throughput 86.45%、issue slots 87.14%，不再是
简单访存等待；平均 active threads/warp 仅 23.9，且 BM=8 对每个 K/V tile 只复用
8 行。

v3 只改变 block rows（BM）和 key tile（BN），online-softmax 数学、FP32 dtype、
寄存器 fragment 布局与输入完全不变。

`B=1,H=8,S=1024,D=128,non-causal`：

|---:|---|---:|---:|---:|
| 0 | 4x16 | 45.219681 ms | 94.980 | 0.79x |
| 1 | 4x32 | 67.153091 ms | 63.958 | 0.53x |
| 2 | 8x16 | 34.495041 ms | 124.510 | 1.03x |
| 3 | 8x32 | 35.646626 ms | 120.487 | 1.00x |
| 4 | 8x64 | 50.756607 ms | 84.619 | 0.70x |
| 5 | 16x16 | 29.718592 ms | 144.521 | 1.20x |
| 6 | 16x32 | 29.122272 ms | 147.480 | 1.22x |
| 7 | 16x64 | 30.380993 ms | 141.370 | 1.17x |
| 8 | **32x32** | **28.796127 ms** | **149.151** | **1.24x** |

causal 同形状中 config 8 仍最快：14.867360 ms；config 6 为 14.976736 ms，差
0.74%。D128 的 BN64 会使用 64 KiB shared 并限制 block 并发，config 4 明显退化；
因此不能只以“barrier 次数更少”选择更大 BN。

## 4. D=64 扫描

`B=1,H=8,S=1024,D=64,non-causal` 的主要候选：

| config | BMxBN | Median | Dense GFLOP/s |
|---:|---|---:|---:|
| 2 | 8x16 | 28.844576 ms | 74.450 |
| 3 | 8x32 | 28.303232 ms | 75.874 |
| 4 | 8x64 | 29.208927 ms | 73.521 |
| 5 | 16x16 | 26.306623 ms | 81.633 |
| 6 | 16x32 | 25.912704 ms | 82.874 |
| 7 | **16x64** | **25.594303 ms** | **83.905** |
| 8 | 32x32 | 27.253759 ms | 78.796 |

causal 下 config 7 也是最佳：13.239232 ms。D64 的 BN64 只需 32 KiB shared，
减少 barrier 的收益能够保留；BM32/1024 threads 则因每 lane 只有两个 D fragments，
更大的 block 没有 D128 那么合算。

S=128 时 block 数较少，config 8 对 D64/D128 分别为 0.419264/0.455008 ms，是
扫描最佳或接近最佳。因此 dispatcher 固化为：

```text
S <= 128      -> config 8: BM32, BN32
S > 128,D<=64 -> config 7: BM16, BN64
S > 128,D>64  -> config 8: BM32, BN32
```

## 6. 正确性与 sanitizer

tile 只改变 block ownership，输出与 v2 bitwise 接近：小尺寸最大绝对误差仍不超过
`3.73e-8`，extreme 输入沿用 v2 的 `9.84e-7`。

自动 config 8 的 `B1,H1,S37,D71,causal=1`：memcheck 0 errors、racecheck 0
hazards、synccheck 0 errors，CPU double reference PASS。它覆盖 1024-thread block
尾行、非整齐 D、causal 尾 tile 和 shared K/V 同步。

## 7. Nsight Systems 与 Compute

S=128,D=64：nsys 单 kernel median 从 v2 `0.446592 ms` 降为 v3
`0.414480 ms`，快 7.75%，与正式 Event 的 7.68% 一致。

| NCU 指标 | v2 BM8xBN32 | v3 BM32xBN32 | 解释 |
|---|---:|---:|---|
| Duration | 450.72 us | **422.05 us** | -6.4% |
| Compute throughput | 86.45% | 86.37% | 仍为高 compute 利用 |
| Issue slots busy | 87.14% | 87.11% | 调度效率相近 |
| Warp cycles/instruction | 12.07 | **9.19** | 更大 BM 改善复用/指令摊销 |
| Registers/thread | 38 | 40 | 无 spill |
| Achieved occupancy | 87.72% | **66.72%** | 1024-thread block 限制 |
| Shared store bank conflict | 未提示 | 1.2-way，4419 | v4 仍需关注 |

v3 再次说明 occupancy 不是独立目标：尽管从 87.7% 降至 66.7%，跨 32 行复用同一
K/V tile 和更少 block 级加载使性能更高。NCU 当前主要建议仍是低 active lanes
（23.3，predicated-on 19.2）和约 1.2-way shared store conflict。

## 8. 下一步

v4 保留 dispatcher 和 tile，只把 online update 按两个相邻 key 分组：同时计算
两个独立 dot accumulators，以共同的 `m_new` 一次 rescale 原有 O，并执行
`O=alpha*O+beta0*V0+beta1*V1`。预期减少 alpha/exp 与串行状态更新次数；若收益
不足 3% 或退化，将保留为负优化，不改动 v3 final candidate。
