# Attention v1：合并 QK 访问并融合 block Softmax

## 1. 来自 v0 的证据

v0 在 `B=1,H=8,S=128,D=64` 的 nsys 中，QK 占 GPU kernel 时间 81.6%；NCU
显示 QK 的 L1/TEX throughput 为 98.41%，compute 只有 6.03%，每线程平均仅使用
每个 32-byte sector 中的 4 bytes。约 85% global sectors 被标为 excessive，
LG throttle 占 warp 指令间隔约 89.2%。

因此 v1 不改变精度、不移除 score 缓冲、不优化 PV，只做两项彼此相关的改变：

1. 重映射 QK，让一个 warp 协作计算一个 `(query,key)` dot-product；
2. QK 结束后在同一 block 内执行 stable Softmax，减少一次 launch 和中间读回。

## 2. kernel 设计

一个 256-thread block 处理一个 query row：

- 8 个 warps 每次并行处理 8 个 key columns；
- lane 沿 D 以步长 32 读取，因此同一 warp 的 K 地址连续；
- query row 先加载到 dynamic shared memory，避免每个 key 重读 global Q；
- `__shfl_down_sync` 规约每个 dot-product；
- 所有 scores 写入 global `[B,H,S,S]` 后，用 block max/sum reduction 就地变为
  probabilities；
- PV kernel 与 v0 完全相同。

保留显式概率矩阵是有意的实验控制：v1 只回答“访问重映射和融合是否解决 v0
瓶颈”，v2 才回答“不落盘 online softmax 有多少额外收益”。

## 3. 正确性与 sanitizer

| B,H,S,D | causal | 最大绝对误差 | 最大行和误差 | 结果 |
|---|---:|---:|---:|---|
| 1,2,32,64 | 0 | `1.49e-8` | `9.69e-8` | PASS |
| 1,2,37,71 | 1 | `2.98e-8` | `1.08e-7` | PASS |
| 1,8,128,64 | 0 | `8.44e-9` | `1.37e-7` | PASS |
| 1,8,128,128 | 1 | `4.47e-8` | `1.23e-7` | PASS |

`S=37,D=71` 覆盖 warp 尾部、非整齐 D 和 causal 上三角。memcheck 在该形状上
报告 `ERROR SUMMARY: 0 errors`，且 CPU double reference PASS。

大形状使用 finite-output 与全部 probability row-sum 检查；S=2048 最大行和误差
为 `1.24e-7`。

## 4. 正式性能与 v0 对照

测量环境与 v0 相同：锁频 Orin Nano Super，warmup 5、repeat 15 的 median。

| B | H | S | D | causal | v0 | v1 | v1 性能 | 加速 |
|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| 1 | 8 | 128 | 64 | 0 | 1.332928 ms | 0.470240 ms | 71.356 GFLOP/s | 2.83x |
| 1 | 8 | 128 | 128 | 1 | 1.461408 ms | 0.479680 ms | 139.903 GFLOP/s | 3.05x |
| 1 | 8 | 512 | 64 | 0 | 21.170303 ms | 6.948672 ms | 77.262 GFLOP/s | 3.05x |
| 1 | 12 | 1024 | 128 | 0 | 237.440582 ms | **53.031170 ms** | **121.484 GFLOP/s** | **4.48x** |
| 1 | 12 | 1024 | 128 | 1 | 134.412003 ms | 38.071999 ms | 169.218 GFLOP/s | 3.53x |
| 1 | 8 | 2048 | 128 | 0 | 632.985168 ms | 140.064804 ms | 122.657 GFLOP/s | 4.52x |

v1 对所有形状均有显著提升，且序列越长、D=128 时收益总体越高。score buffer
大小完全不变：主形状仍需 48 MiB，`B=1,H=12,S=4096` 仍会达到 768 MiB。

## 5. Nsight Systems

形状 `B=1,H=8,S=128,D=64,causal=0`：

| 版本/kernel | Median | GPU kernel 时间占比 |
|---|---:|---:|
| v0 `qk_kernel` | 1.085488 ms | 81.6% |
| v0 `softmax_serial_kernel` | 0.156752 ms | 12.1% |
| v0 `pv_kernel` | 0.084224 ms | 6.4% |
| v1 `qk_softmax_kernel` | **0.383488 ms** | 83.1% |
| v1 `pv_kernel` | 0.084368 ms | 16.9% |

v1 融合 kernel 比 v0 QK+Softmax 的 1.242240 ms 快 3.24x；PV 的 0.084224→
0.084368 ms 基本不变。这排除了“PV 或运行波动造成整体加速”的解释。

## 6. Nsight Compute 对照

同一 S=128,D=64 的 QK 主阶段：

| 指标 | v0 QK | v1 QK+Softmax | 变化 |
|---|---:|---:|---|
| Duration | 1.09 ms | 491.04 us | -55%（NCU 多 pass 绝对值仅作同轮诊断） |
| L1/TEX throughput | 98.41% | **44.77%** | 访问重映射生效 |
| L2 throughput | 1.76% | 14.18% | 数据层级更均衡 |
| Compute throughput | 6.03% | **64.93%** | 从纯访存等待转向计算/控制 |
| Issue slots busy | 4.24% | **65.21%** | 15.4x |
| No eligible warp | 95.75% | **34.78%** | -60.97 pp |
| Warp cycles/instruction | 268.45 | **14.92** | -94.4% |
| Achieved occupancy | 94.83% | 81.27% | 略降但性能大幅上升 |
| Registers/thread | 37 | 48 | 融合规约状态的代价 |

v0 的“global load 每 sector 只用 4 bytes”警告消失。v1 新的主要提示是 global
probability store 平均每 sector 仅利用 9.6/32 bytes，估计潜在改进 31.2%；这是
lane 0 分散写各 key score 和随后全 block 重写 probabilities 导致的，也是 v2
完全不写 S² 的直接动机。

v1 仍有约 31.5% warp 指令间隔来自 long scoreboard；平均 active threads/warp
27.2、predicated-on 24.0，说明 warp-per-key 在 D 尾部与 reduction 控制流上仍有
浪费。但在显式 S² 即将被移除前，不继续微调这条临时路径。

## 7. 结论与下一步

v1 证明 v0 的 Nsight 诊断正确：即使 achieved occupancy 从 94.8% 降到 81.3%，
合并访问仍使主形状加速 4.48x。当前瓶颈已从 uncoalesced QK load 转为显式
probability store、S² 容量及仍然独立的 PV 扫描。

v2 将使用 query/key block tiling 和 online softmax，在 FP32 中维护每行 `(m,l,O)`，
不分配 `[B,H,S,S]`。这是算法/数据流层面的变化，将单独报告显存下降、数值误差、
tile 资源和相对 v1/v0 的收益。
