# Attention v7：shared padding 与并行 QK 分片实验

## 1. 问题与版本拆分

v6 的 NCU 证据同时指向两个问题：shared load 平均 4-way bank conflict，且 QK 阶段
只有 warp 0 执行 WMMA。为了避免把两个改动混成一个不可解释的结果，v7 保留两个
可通过 `--config` 选择的小版本：

- **v7.0（`--config=1`）**：padded shared layout，并让 `D/16` 个 warp 各自计算一个
  K 维 partial QK tile，再显式归并 partial score；
- **v7.1（默认 `--config=0`）**：保留 v6 的单 warp 直接累加 QK，只测试 padded
  shared layout 的独立效果。

两者都维持 FP16 Q/K/V、Tensor Core QK/PV、FP32 online `(m,l,O)`，不保存
`[B,H,S,S]`。非 `D=64/128` 或 `S%16!=0` 的形状仍走 FP16 输入、FP32 计算的
scalar online fallback。

## 2. v7.0：并行 partial QK

### 2.1 实现过程

最初尝试直接把 padded leading dimension 设成 `D+1`（FP32 输出为 17）。WMMA
`load/store_matrix_sync` 对 leading dimension 有对齐约束，该版本虽然可编译，却在
运行时产生错误结果。修正后使用：

- Q/K/V：`D+8` 个 half；
- probability：24 个 half；
- score：20 个 float；
- output/PV：`D+4` 个 float。

随后每个 QK warp 只执行一次 `16x16x16` WMMA，把 partial score 写入独立 shared
区域；256 个线程再归并 `D/16` 个 partial。该结构把 QK 的 tensor-core 工作分给
多个 warp，但增加了 shared 容量、一次 CTA 同步、partial store/load 和标量归并。

### 2.2 结果

| B | H | S | D | causal | v6 | v7.0 | v7.0/v6 |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 1 | 12 | 1024 | 128 | 0 | 20.732800 ms | 27.817663 ms | 0.745x |
| 1 | 12 | 1024 | 128 | 1 | 10.829312 ms | 14.343968 ms | 0.755x |
| 1 | 8 | 2048 | 128 | 0 | 55.918430 ms | 74.090431 ms | 0.755x |
| 1 | 8 | 4096 | 128 | 0 | 223.637283 ms | 295.499969 ms | 0.757x |

ptxas 报告 52 registers/thread、0 spill，D128 dynamic shared 为 41,152 bytes。
结论是“增加活跃 QK warps”并不等于端到端加速：partial score 的写回、归并和同步
成本大于单 warp 连续 WMMA 累加节省的等待，长序列稳定慢约 25%。v7.0 作为负优化
保留，不进入 dispatcher。

## 3. v7.1：只做 shared padding

v7.1 去掉 parallel partial 和归并，恢复 v6 的单 warp QK accumulator；其余 padded
布局不变。ptxas 为 50 registers/thread、0 spill；dynamic shared 为 D64 17,856
bytes、D128 32,192 bytes。

| B | H | S | D | causal | v6 | v7.1 | v7.1/v6 |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 1 | 8 | 128 | 64 | 0 | 0.152320 ms | 0.153728 ms | 0.991x |
| 1 | 8 | 128 | 128 | 1 | 0.173984 ms | **0.169024 ms** | **1.029x** |
| 1 | 8 | 512 | 64 | 0 | 2.034496 ms | 2.096288 ms | 0.971x |
| 1 | 12 | 1024 | 128 | 0 | 20.732800 ms | 21.634432 ms | 0.958x |
| 1 | 12 | 1024 | 128 | 1 | 10.829312 ms | 11.223008 ms | 0.965x |
| 1 | 8 | 2048 | 128 | 0 | 55.918430 ms | 57.540833 ms | 0.972x |

只有短序列 causal D128 提升 2.9%，未达到 3% 采用门槛；主形状慢 4.35%。因此也不
把 padded layout 加入最终 dispatcher。

## 4. Nsight 解释：冲突消失为何仍然变慢

分析形状为 `B1,H8,S128,D128,non-causal`：v7.1 nsys 单 kernel median 为
238.688 us，v6 为 239.184 us，短形状几乎持平。NCU 对照如下：

| 指标 | v6 | v7.1 |
|---|---:|---:|
| NCU Duration | 269.54 us | **246.75 us** |
| Compute / Memory throughput | 49.16% / 59.67% | 61.64% / 31.45% |
| Issue slots busy | 50.01% | **62.63%** |
| No eligible warp | 49.97% | **37.26%** |
| Warp cycles/instruction | 16.57 | **11.49** |
| Registers/thread | 47 | 50 |
| Achieved occupancy | 68.65% | 59.86% |
| Executed instructions | 3,995,648 | **4,909,568** |
| Excessive shared wavefronts | 655,872（约 59%） | **69,120（约 13%）** |

padding 确实消除了 NCU 的 shared-load 4-way conflict 警告；shared store 只剩平均约
1.3-way、518,588 conflicts。但 padding 同时引入更多地址计算与搬运：执行指令增加
22.9%，寄存器从 47 增至 50，实际 occupancy 下降。短序列可由冲突下降抵消这些
成本，长序列则被额外指令持续放大。这说明 NCU 单项指标改善必须回到端到端 median
验证，不能直接当成优化成功。

## 5. 正确性与 sanitizer

| 路径/形状 | causal | extreme | 最大绝对误差 | 结果 |
|---|---:|---:|---:|---|
| v7.1 WMMA `B1,H2,S32,D64` | 0 | 0 | `2.71e-5` | PASS |
| v7.1 WMMA `B1,H2,S32,D128` | 1 | 0 | `4.56e-5` | PASS |
| v7.1 WMMA `B1,H2,S64,D128` | 0 | 1 | `8.22e-5` | PASS |
| fallback `B1,H2,S37,D71` | 1 | 0 | `<1e-7` | PASS |

`B1,H1,S32,D128,causal=1` 的 memcheck 为 0 errors、racecheck 为 0 hazards、
synccheck 为 0 errors。FP16 判定继续使用量化输入的 double CPU reference 和
`abs_error <= 2e-2 + 2e-2*abs(reference)`；实测最大绝对误差比阈值小两个数量级。

## 6. 最终版本稳定性与压力测试

v7 两个实验均未达到采用门槛，因此 **v6 是本阶段最终 FP16 FlashAttention
kernel**。主形状 `B1,H12,S1024,D128,non-causal` 在五个独立进程中的 median 为：

```text
20.789921, 20.824608, 20.786560, 20.796640, 20.804001 ms
```

极差/均值约 0.18%，低于 3% 稳定性要求。`B1,H8,S4096,D128,non-causal` 压力测试
为 223.637283 ms、307.281 dense GFLOP/s，正确性 PASS，仍无 S² 中间缓冲。

主形状 v0 显式 score 缓冲为 48 MiB，v6/v7 为 0，即 attention 中间矩阵减少
48 MiB（100%）。若只按程序实际分配的 Q/K/V/output/score payload 统计，FP32 v0
为 72 MiB，FP16-input/FP32-output v6 为 15 MiB，下降 79.2%；该总量同时包含 dtype
变化，简历应优先表述“消除 48 MiB S² 中间矩阵”。

## 7. cuDNN 对比审计

设备当前 CUDA 12.6 / cuDNN 9.3 开发环境没有 cuDNN Frontend SDPA headers；历史
目录仅有 deprecated `cudnnMultiHeadAttnForward` FP32 wrapper。重新运行该旧程序
得到 4.431 ms average，但它包含 identity projection 配置、逐 head 调用，且采用
FP32/average 口径，不能与新项目 FP16 kernel 的 CUDA Event median 构成公平比例。

因此本阶段不伪造“相对 cuDNN 百分比”，也不把该 4.431 ms 写入简历。等后续进入
统一依赖环境时，再用同 dtype、同 mask、同 shape、同 warmup/repeat/median 的 SDPA
接口补测；这不会改变本阶段 standalone kernel 的基准记录。

## 8. 阶段结论

- v0→v5 完成 FP32 naive、融合、online softmax、tile 扫描和 cp.async 演进；
- v6 完成 FP16 Tensor Core QK/PV、FP32 online softmax，并成为当前 final；
- v7.0 证明 parallel partial QK 的同步/归并成本过高；
- v7.1 证明 bank conflict 大幅下降仍可能因指令数和 occupancy 退化而负优化；
- baseline/final、非对齐 fallback、causal、extreme、sanitizer、nsys/ncu、稳定性和
  S=4096 压力测试均已有可复现记录。

FlashAttention standalone 阶段至此暂停，不继续工程化或 PyTorch Extension。
