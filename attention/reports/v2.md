# Attention v2：tiled online softmax，不保存 S²

## 1. 目标

v1 已修复 QK 的非合并访问，但仍把 `[B,H,S,S]` probability 写入 global，再由
PV 读取。在 `B=1,H=12,S=4096` 时，这个 FP32 中间量单独需要 768 MiB。

v2 第一次改为 FlashAttention 风格数据流：K/V 以 tile 流过 shared memory，每个
query row 在寄存器中维护 online-softmax 状态，不分配或写回 score/probability。
本版仍使用 FP32 FMA，不使用 Tensor Core，以便先验证算法与内存行为。

## 2. online softmax

处理新 score `x` 时，每行保存运行最大值 `m`、指数和 `l` 以及未归一化输出 `O`：

```text
m_new = max(m, x)
alpha = exp(m - m_new)
beta  = exp(x - m_new)
l_new = alpha*l + beta
O_new = alpha*O + beta*V_key
```

扫描结束后只做一次 `O/l`。所有 `m/l/O` 都是 FP32，因而即使输入 score 很大，
指数参数也不会为大正数。

## 3. kernel 布局

| 参数 | v2 |
|---|---:|
| query rows/block（BM） | 8 |
| key tile（BN） | 32 |
| threads/block | 256（8 warps） |
| query row ownership | 一 warp 一行 |
| D fragments/lane | D=64 时 2，D=128 时 4 |
| shared | `2*BN*D*sizeof(float)`，K/V 双数组 |
| global S² intermediate | 0 bytes |

block 中 8 个 warps 复用同一 K/V tile。Q 与 O fragments 保存在寄存器；每个 key
的 dot-product 使用 warp shuffle 规约。causal 模式在整块 query row 都不再需要后续
key tile 时提前结束扫描，并在最后一个 tile 内逐行跳过上三角。

这是第三个版本，因此此时才提取 `attention_common.h`，内容仅限本算子的参数、
数据、CPU double reference、校验和 CUDA Event median；v0/v1 仍保持自包含，
没有建立跨算子公共框架。

## 4. 正确性与数值稳定性

| B,H,S,D | causal | extreme | 最大绝对误差 | 结果 |
|---|---:|---:|---:|---|
| 1,2,32,64 | 0 | 0 | `1.49e-8` | PASS |
| 1,2,37,71 | 1 | 0 | `3.73e-8` | PASS |
| 1,2,64,128 | 0 | 1 | `9.84e-7` | PASS |
| 1,8,128,64 | 0 | 0 | `9.31e-9` | PASS |
| 1,8,128,128 | 1 | 0 | `2.98e-8` | PASS |

`extreme=1` 将 Q/K 幅度扩大 20 倍，使部分未稳定 score 的指数会严重溢出；online
更新仍通过 CPU double reference。最大相对误差会被接近零的参考值放大到 1.79%，
但最大绝对误差仅 `9.84e-7`，满足统一混合阈值。

复杂 shared/同步路径的 sanitizer：

| 工具 | 形状 | 结果 |
|---|---|---|
| memcheck | `B1,H2,S37,D71,causal=1` | 0 errors |
| racecheck | `B1,H1,S37,D71,causal=1` | 0 hazards |
| synccheck | `B1,H1,S37,D71,causal=1` | 0 errors |

三项运行均同时 `correct=PASS`。

## 5. 正式性能

| B | H | S | D | causal | v0 | v1 | v2 | 相对 v1 | 相对 v0 |
|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| 1 | 8 | 128 | 64 | 0 | 1.332928 | 0.470240 | **0.451168 ms** | 1.04x | 2.95x |
| 1 | 8 | 128 | 128 | 1 | 1.461408 | 0.479680 | **0.334944 ms** | 1.43x | 4.36x |
| 1 | 8 | 512 | 64 | 0 | 21.170303 | 6.948672 | **6.780352 ms** | 1.02x | 3.12x |
| 1 | 12 | 1024 | 128 | 0 | 237.440582 | **53.031170** | 56.123711 ms | **0.945x，负优化** | 4.23x |
| 1 | 12 | 1024 | 128 | 1 | 134.412003 | 38.071999 | **28.929184 ms** | **1.32x** | 4.65x |
| 1 | 8 | 2048 | 128 | 0 | 632.985168 | **140.064804** | 149.291519 ms | **0.938x，负优化** | 4.24x |

主 non-causal 形状从 v1 的 53.031 ms 退化到 56.124 ms（慢 5.8%），S=2048
慢 6.6%。该结果明确保留，不用 causal 的正收益掩盖。causal 因跳过未来 key tiles，
反而获得 1.32x v1 和 4.65x v0。

显存方面，v2 的 global S² intermediate 从 48 MiB（主形状）降为 0；S=2048,H=8
从 128 MiB 降为 0。kernel 仍按 block 临时使用 16 KiB（D=64）或 32 KiB
（D=128）shared，这不随 S² 增长，也不是持久 global allocation。

## 6. 资源与 Nsight Systems

ptxas：38 registers/thread、0 spill、1 barrier。D=64 使用 16,384 bytes dynamic
shared；D=128 使用 32,768 bytes。

S=128,D=64 的 nsys：v2 只有一个 kernel，median `0.446592 ms`。对照 v1 的
`qk_softmax 0.383488 + PV 0.084368 = 0.467856 ms`，v2 快约 4.8%，与正式 CUDA
Event 的 4.2% 相符。说明小形状融合和不落盘有小收益，但不会自然外推到长序列。

## 7. Nsight Compute

S=128,D=64 的稳态 online kernel：

| 指标 | v2 | 与 v1 QK+Softmax 的关系 |
|---|---:|---|
| Duration | 450.72 us | 单 kernel 还包含 PV |
| Compute throughput | **86.45%** | v1 64.93% |
| Memory throughput | 61.46% | v1 44.57% |
| L1/TEX throughput | 61.95% | K/V tile 流式加载 |
| Issue slots busy | **87.14%** | v1 65.21% |
| No eligible warp | 12.93% | v1 34.78% |
| Warp cycles/instruction | 12.07 | v1 14.92 |
| Achieved occupancy | 87.72% | 理论 100% |
| Active threads/warp | **23.92** | v1 27.23 |
| Predicated-on threads/warp | **19.77** | v1 23.98 |

v2 已不是 v0 式的 memory-stall kernel：issue 和 compute 很高。NCU 估计低 active
lanes 可能有 33.0% 改进空间；来源包括 lane0 独占 exp/状态更新、D 尾部和循环控制。
non-causal 长序列每个 key 都执行串行 online 状态依赖，BM=8 对 K/V 的复用也较低，
这些计算/同步成本抵消了 S² 写回的节省。

## 8. 决策

v2 的算法方向必须保留，因为它实现了 S² 显存归零并使 causal 明显加速；但当前
配置不作为最终 non-causal 性能版本。v3 将扫描：

- BN=16/32/64，权衡 barrier 次数与 shared/occupancy；
- 128/256 threads，即 BM=4/8，权衡 K/V 复用与 block 并发；
- D=64/128 和 causal/non-causal 分别选择，而不是强行一个 tile 覆盖全部。

若简单 tile 扫描不能改善串行 online 依赖，后续版本再引入多累加器/更粗粒度并行，
不会在 v3 同时叠加多个未验证技巧。
