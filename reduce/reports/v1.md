# Reduce v1：block 内 shared-memory tree reduction

## 1. 优化假设

v0 在主尺寸使用 16,384 个参与线程，每个线程都对同一个地址执行一次
`atomicAdd`。v1 保留相同的 grid-stride 数据读取，只把 block 内线程结果先在
shared memory 中规约，最后由 thread 0 执行一次 atomic。全局 atomic 数量从
最多 16,384 次下降到 64 次。

预期：如果 v0 的主要延迟确实来自全局 atomic 竞争，主尺寸应出现明显提升。

## 2. 唯一实现变化

```cpp
shared[lane] = thread_sum;
__syncthreads();
for (unsigned int offset = blockDim.x / 2; offset > 0; offset >>= 1) {
  if (lane < offset) {
    shared[lane] += shared[lane + offset];
  }
  __syncthreads();
}
if (lane == 0) {
  atomicAdd(output, shared[0]);
}
```

输入生成、64×256 launch 配置、计时方法和 v0 完全相同。实验环境继续保持
MAXN_SUPER、GPU 1020 MHz、EMC 3199 MHz。

## 3. 正确性与性能

| N | 绝对误差 | v0 Median | v1 Median | 加速 | v1 有效带宽 | 正确性 |
|---:|---:|---:|---:|---:|---:|---|
| 32 | 0.000000 | 0.008016 ms | 0.009040 ms | 0.89× | 0.014159 GB/s | PASS |
| 1,000 | 0.000000 | 0.011024 ms | 0.009312 ms | 1.18× | 0.429553 GB/s | PASS |
| 1,024 | 0.000000 | 0.011200 ms | 0.009328 ms | 1.20× | 0.439108 GB/s | PASS |
| 4,096 | 0.000001 | 0.020400 ms | 0.009584 ms | **2.13×** | 1.709516 GB/s | PASS |
| 1,048,576 | 0.000061 | 0.145088 ms | 0.102640 ms | 1.41× | 40.864223 GB/s | PASS |
| 16,777,216 | 0.000916 | 1.504416 ms | **1.473408 ms** | **1.02×** | **45.546695 GB/s** | PASS |

shared-memory reduction 显著改善了中小尺寸，并改善了求和误差。但在主尺寸
上只快 2.1%，低于 3% 的“有效优化”门槛。

## 4. Nsight Systems

主尺寸三个 kernel 实例的 median 为 **1.460800 ms**，与独立 benchmark 的
1.473408 ms 一致。v0 对应值为 1.493120 ms，确认主尺寸改善确实很小，而非
benchmark 噪声造成。

## 5. Nsight Compute 对比

| 指标 | v0 | v1 | 变化 |
|---|---:|---:|---:|
| Memory throughput | 30.53% | 30.90% | 基本不变 |
| Compute throughput | 9.66% | 9.98% | 基本不变 |
| Issue slots busy | 11.05% | 12.24% | 小幅改善 |
| No eligible warp | 90.27% | 88.59% | 改善有限 |
| Active warps / scheduler | 7.99 | 9.19 | 增加 |
| Eligible warps / scheduler | 0.10 | 0.13 | 仍然极低 |
| Warp cycles / issued instruction | 82.12 | 80.53 | 基本不变 |
| L1TEX scoreboard stall | 75.5 cycles / 91.9% | 73.9 cycles / 91.7% | 基本不变 |
| Achieved occupancy | 75.61% | 82.06% | 增加 |
| Registers / thread | 16 | 16 | 不变 |
| Dynamic shared memory / block | 0 | 1.02 KB | 增加 |

atomic 数量已经下降 256 倍，但最关键的 L1TEX scoreboard 指标几乎没有变化。
因此 v0 的 ncu 提示不能简单解释为 atomic 竞争；它同时包含 grid-stride 循环中
标量全局加载及串行 `thread_sum += input[i]` 依赖带来的等待。

## 6. 结论

原假设只在短输入上成立。v1 值得保留，因为它显著改善了中小尺寸、减少了
atomic 并提高了数值稳定性；但它不是主尺寸的决定性优化。

下一步 v2 只用 warp shuffle 替换 block reduction 尾部，减少 shared-memory
访问和 8 次全 block 同步。由于主尺寸时间主要在数据读取阶段，预期 v2 对大
尺寸提升有限，但能验证 reduction 尾部在小尺寸和主尺寸中的实际占比。
