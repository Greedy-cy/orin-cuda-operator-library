# Reduce v2：warp shuffle reduction tail

## 1. 优化假设

v1 使用 8 轮 shared-memory tree reduction，每轮都有一次全 block 同步。v2
保持数据读取、grid、block 和每 block 一次 atomic 不变，只把最后一个 warp
的规约改成 `__shfl_down_sync`。

预期：小尺寸中 reduction tail 占比较高，因此可能改善；主尺寸主要卡在全局
加载，预计变化有限。

## 2. 唯一实现变化

shared-memory reduction 只执行 offset=128 和 64 两轮，最后 64 个值由一个
warp 处理：

```cpp
if (lane < warpSize) {
  float value = shared[lane] + shared[lane + warpSize];
  for (int offset = 16; offset > 0; offset >>= 1) {
    value += __shfl_down_sync(0xffffffff, value, offset);
  }
  if (lane == 0) atomicAdd(output, value);
}
```

## 4. Nsight Systems

主尺寸三个 kernel 实例的 median 为 **1.467424 ms**。对应 v1 为
1.460800 ms，两者可视为持平。

## 5. Nsight Compute 对比

| 指标 | v1 | v2 | 解释 |
|---|---:|---:|---|
| Memory throughput | 30.90% | 30.89% | 完全不变 |
| Compute throughput | 9.98% | 10.98% | shuffle 增加少量计算活动 |
| Issue slots busy | 12.24% | 13.15% | 略有改善 |
| No eligible warp | 88.59% | 86.86% | 略有改善但仍很高 |
| Active warps / scheduler | 9.19 | 10.66 | 增加 |
| Eligible warps / scheduler | 0.13 | 0.15 | 仍然极低 |
| Warp cycles / issued instruction | 80.53 | 81.09 | 无改善 |
| L1TEX scoreboard stall | 73.9 cycles / 91.7% | 74.4 cycles / 91.8% | 无改善 |
| Achieved occupancy | 82.06% | 88.74% | 明显提高但未转化为性能 |

v2 提高了 active warp 和 occupancy，却没有提高主尺寸吞吐。这说明问题不是
简单的 occupancy 不足，而是每个 warp 的标量 load-add 依赖链使绝大多数 active
warp 同时处于等待状态。继续减少 reduction tail 指令不会解决问题。

## 6. 结论与下一步

v2 是一个有证据支持的“主尺寸无收益”版本：warp shuffle 对短输入合理，但
大输入时间完全由数据读取/累加阶段主导。

v3 将使用四个彼此独立的累加器，每次循环发出四组相隔一个 grid stride 的
合并加载，让编译器可以交错 load-add 指令并用 ILP 隐藏全局内存延迟。grid 和
规约尾部保持不变，以便单独验证多累加器的作用。
