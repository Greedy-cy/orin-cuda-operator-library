# Reduce v4：float4 向量化加载

## 1. 优化假设

v3 已达到 93.43 GB/s，并在 ncu 中表现为 memory-bound。v4 保留四个累加器、
warp shuffle 和每 block 一次 atomic，只把每轮四条标量全局 load 改成一条
128-bit `float4` load。目标是减少 load 和循环指令，同时维持四个分量的独立
累加。

输入来自 `cudaMalloc`，满足 `float4` 对齐要求；`N % 4` 的最后 0–3 个元素
使用标量 tail 处理。

## 2. 实现变化

```cpp
const float4 value = vector_input[i];
sum0 += value.x;
sum1 += value.y;
sum2 += value.z;
sum3 += value.w;
```

与 v3 的区别仅在数据读取映射。主尺寸仍使用 64×256 launch。

## 4. Nsight Systems

主尺寸三个 kernel 实例的 median 为 **0.718560 ms**；v3 为 0.710912 ms。
两种测量都确认 v4 没有超过 v3。

## 5. Nsight Compute 对比

| 指标 | v3 | v4 | 变化 |
|---|---:|---:|---:|
| Memory throughput | **75.69%** | 69.91% | 下降 |
| Compute throughput | 13.46% | 6.33% | 指令工作减少 |
| Issue slots busy | 15.55% | 7.20% | 下降 |
| No eligible warp | 83.89% | **92.50%** | 明显恶化 |
| Eligible warps / scheduler | 0.18 | 0.08 | 下降 55.6% |
| Warp cycles / issued instruction | 62.27 | **138.48** | 增加 2.22× |
| L1TEX scoreboard stall | 58.0 cycles | **132.6 cycles** | 增加 2.29× |
| Registers / thread | 30 | 16 | 下降 |
| Achieved occupancy | 80.62% | 83.13% | 略升 |
| Executed instructions | 3,574,464 | **1,606,848** | 下降 55.0% |

v4 的指令数和寄存器都显著减少，occupancy 也略升，但性能没有提升。关键原因
是 v3 的四条标量 load 是四个可以独立在途的内存请求，而 v4 的四个分量依赖
同一条 `float4` load 返回。向量化减少了指令，却也减少了 memory-level
parallelism，使 eligible warp 下降、scoreboard 等待翻倍。

因此“更宽的 load 指令一定更快”在此处不成立。全局访问原本已经合并，实际
DRAM 字节数不变，减少指令无法补偿 MLP 的损失。

## 6. Sanitizer

以下检查均为 0 errors：

- v3 `compute-sanitizer --tool memcheck --n=1003`
- v3 `compute-sanitizer --tool synccheck --n=1003`
- v4 `compute-sanitizer --tool memcheck --n=1003`

这同时验证了 v3 的 shuffle/barrier 使用和 v4 的非对齐标量 tail。

## 7. 收口结论

- 大尺寸最终实现选择 **v3**：0.718256 ms、93.433 GB/s、相对 v0 2.09×。
- v4 在约 1K 元素时略快，可作为未来 dispatcher 的小尺寸候选。
- v4 不作为大尺寸默认实现，但完整保留为向量化负优化案例。
- 下一步不再继续压榨 Reduce，转入 Softmax；Softmax 将直接复用本实验得到的
  reduction 和 ILP 认识，但不会立即抽象公共框架。
