# Reduce v3：四累加器 ILP

## 1. 优化假设

v2 已达到 88.74% occupancy，但 86.86% 的周期仍无 eligible warp，单个 warp
有 91.8% 的发射间隔在等待 L1TEX scoreboard。这说明继续增加 occupancy 或
优化 reduction tail 的价值有限。

v3 保持 64×256 launch、warp-shuffle tail 和每 block 一次 atomic 不变，将每
线程的一条串行 load-add 累加链拆成四条独立累加链。目标是同时保持多笔全局
加载在途，用 ILP 隐藏延迟。

## 2. 唯一实现变化

```cpp
for (; i + 3 * stride < n; i += 4 * stride) {
  sum0 += input[i];
  sum1 += input[i + stride];
  sum2 += input[i + 2 * stride];
  sum3 += input[i + 3 * stride];
}
shared[lane] = (sum0 + sum1) + (sum2 + sum3);
```

四组地址在各自的 warp 指令中仍连续，因此没有牺牲全局访存合并。

## 3. 正确性与性能

| N | 绝对误差 | v2 Median | v3 Median | 相对 v2 | v3 有效带宽 | 正确性 |
|---:|---:|---:|---:|---:|---:|---|
| 32 | 0.000000 | 0.008352 ms | 0.008528 ms | 0.98× | 0.015009 GB/s | PASS |
| 1,000 | 0.000000 | 0.009232 ms | 0.009136 ms | 1.01× | 0.437828 GB/s | PASS |
| 1,024 | 0.000000 | 0.009184 ms | 0.009136 ms | 1.01× | 0.448336 GB/s | PASS |
| 4,096 | 0.000001 | 0.009328 ms | 0.009296 ms | 1.00× | 1.762478 GB/s | PASS |
| 1,048,576 | 0.000031 | 0.101712 ms | **0.055312 ms** | **1.84×** | 75.829910 GB/s | PASS |
| 16,777,216 | 0.000122 | 1.473456 ms | **0.718256 ms** | **2.05×** | **93.433072 GB/s** | PASS |

相对 v0 的主尺寸总加速为 **2.09×**。ILP 对短输入没有帮助，因为短输入主要
由 launch 和 reduction tail 决定；输入足够大后收益非常显著。

## 4. Nsight Systems

主尺寸三个实例的 median 为 **0.710912 ms**，独立 benchmark 为 0.718256 ms。
相对 v2 的 nsys median 1.467424 ms，加速约 2.06×。

## 5. Nsight Compute 对比

| 指标 | v2 | v3 | 变化 |
|---|---:|---:|---:|
| Memory throughput | 30.89% | **75.69%** | 2.45× |
| Compute throughput | 10.98% | 13.46% | 轻微增加 |
| Issue slots busy | 13.15% | 15.55% | 增加 |
| No eligible warp | 86.86% | 83.89% | 小幅下降 |
| Warp cycles / issued instruction | 81.09 | **62.27** | 降低 23.2% |
| L1TEX scoreboard stall | 74.4 cycles | **58.0 cycles** | 降低 22.0% |
| Achieved occupancy | 88.74% | 80.62% | 因寄存器增加而下降 |
| Registers / thread | 16 | 30 | 增加 |
| Executed instructions | 4,742,848 | 3,574,464 | 下降 24.6% |

虽然寄存器从 16 增加到 30、occupancy 下降到 80.62%，性能反而翻倍。关键是
ILP 缩短了 scoreboard 等待，并把内存吞吐从 30.89% 推到 75.69%。该结果说明
本场景中更多 active warp 不如每个 warp 拥有更多独立工作有效。

ncu 现在将 kernel 明确判断为 Memory 比 Compute 使用更重，并指出主要限制位于
L2/内存路径。有效带宽 93.43 GB/s 已接近此前硬件画像约 100 GB/s 的流式读上限。

## 6. 结论与下一步

v3 是第一个决定性优化版本，验证了“用 ILP 隐藏内存延迟”的假设。下一步 v4
把四次标量 load 改为一次 128-bit `float4` load，同时保留四个累加器。若访问
已经完全合并，向量化可能只减少指令而不会减少实际 DRAM transaction；因此
v4 既可能小幅提升，也可能因每线程工作映射变化而持平，是需要实测的问题。
